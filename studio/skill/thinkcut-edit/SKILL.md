# 剪辑（thinkcut-edit）

> **路径和 IP**（2026-11-24 配置档）：下文 `$AI` 是程序目录：`AI=$(cd -P ~/.claude/skills/thinkcut-edit/../../.. && pwd)`（技能链接指着的使用版；在开发版试验时换成开发版目录）。`<片子文件夹>`、`<试验田>`、`<回收站>` 是这个 IP 配置的位置，用 `python3 "$AI/bin/thinkcut_config.py" show --key 片子文件夹` 查（默认是程序目录旁边的 `<IP 名>视频/`、`<IP 名>试验田/`、`#recycle/`）。做哪个项目先读它所属 IP 的规矩：`python3 "$AI/bin/thinkcut_config.py" rules --project <项目根>`（在用户配置档 `<IP>/规矩.md`；用户配置档默认是程序目录旁边的 `ThinkCut配置档/`，`python3 "$AI/bin/thinkcut_config.py" where` 查），和这里冲突时以那份为准。


**接到一个新项目任务（“剪一下这条片子”“剪一下这个项目”“做这条”，用户在审片台文稿栏定稿后点了“开始制作”（`--wait` 打印“用户点了开始制作”），或只丢来文案、口播录像）：先读 [references/初稿模式.md](references/初稿模式.md)，照它的清单把口播剪辑、动画和画面、审核线、封面、上传文案五项一口气做成初稿发到审片台，中间不问用户；缺口播用机器配音占位、缺画面用生成图占位**（2026-11-22 用户定：“按照AI的想法直接做就行了，不用来问我，等做完了我边看边改……像一个剪辑师一样，先给我做出来”）。只留两道闸：整片 4K 导出要用户在审片台点过审片栏“定稿”，上传发布由用户自己在蚁小二里点。

一个项目按 1→7 走。用户只要其中一步时，**先按下表找到这次要做的那一步，只读那一步的说明，照做。**一次要做好几步就按顺序做，做完一步再读下一步。判断不了是哪一步时用一句话问用户。

## 所有步骤都遵守

- **用户手改过的都不再改**：用户在达芬奇里手改过的片段、字幕、花字、音效就是定稿，不批量覆盖、不重建；详细规则见 `$AI/core/AGENTS.md`。
- **可以用 Fusion**（2026-10-23）：跟踪、抠图、背景模糊等需要时直接用，在独立复合片段里做；要在达芬奇里能改字、要跟着物体走的花字（跟随标签、对比标签，按第 4 步的 fx 说明做）用剪辑页 Text+，不用 Fusion 做字；其余花字和卡片用包装系统（上表第 4 步）。
- **产物都放本期项目文件夹**：`<项目文件夹>/02_制作/` 下（项目文件夹通常在 `<片子文件夹>/<项目名>/`，也可能在别的 NAS 路径；动画成片的项目目录是 `02_制作/自动剪辑/`），不散落到别处。这台 Mac 上不存项目的东西（2026-10-29 用户定）。
- **达芬奇工程只建在项目自己的库**（2026-10-29）：库名就是项目文件夹名，位置 `02_制作/达芬奇工程`，`thinkcut-project` 建项目时登记。新建或导入工程前先切到这个库，不用本机库（Local Database），也不用别的库；工程建好后把缓存和调色静帧位置设到项目文件夹（`$AI/projects/bin/resolve_library.py` 的 `use_project_folder`）。**达芬奇开着也不用让用户退出、不用问**（2026-11-23 初稿模式实测）：`deliver` 自动先跑 `project.py resolve-open 项目目录`——库列表里没有这个项目的库时借用当前开着的磁盘库建工程（记在 `项目.json`，存档后迁回），切走用户开着的工程前先保存并记进 `02_制作/达芬奇切换记录.json`，做完停在新项目上，汇报时说一句“达芬奇从《X》切到了这个项目，要回去说一声”。
- **口播剪完、字幕校对完就直接放进达芬奇**，不用再问。
- **返修换进达芬奇后**，改动处加绿色时间线标记“改：…”；交付文件在 Finder 里直接打开；给用户看的提示、按钮都用中文。
- **做项目的会话不改这些能力本身**（程序、规则、说明、花字库、音效库和收藏表，2026-11-01 用户再次确认）：发现要改的，用 thinkcut-feedback（用户说“反馈”）整理成反馈单直接交给“架构审查”（2026-11-22 起不在对话里和用户逐条确认），由它看全局决定改不改、按占位→测试→存档改。所有剪辑能力都在 `$AI`。
- **说“完成／已生效／会自动……”之前要有依据**（2026-11-12《水电》：把旧文件当新渲染报“已出完”、说“会自动截取标签”其实不会、把封面位置说错）：汇报里附上这次的依据——当次命令输出、文件修改时间或路径；没核实的明说“还没核实”，不说“会自动”除非程序里真有这一步。
- **随手记反馈**（2026-11-11）：用户每纠正一处、返修一处、新定一条规矩，或 AI 自己查出问题、工具报错绕路，马上在 `<项目文件夹>/02_制作/反馈记录.md` 末尾加一行 `时间 | 环节 | 谁先发现（用户/AI自查/工具拦下） | 发生了什么（用户原话） | 当时怎么处理`——用 `python3 scripts/thinkcut_edit.py note <项目目录或项目文件夹> --step 环节 --who 用户|AI自查|工具拦下 --what "…" --how "…"` 记，时间自动用电脑的钟，不手写时间（2026-11-23：手写的时间是估的，和审片台记的对不上）；用户完整看完一轮提意见时先加 `## 第 N 轮审核`。不问用户、不发给用户，thinkcut-feedback 用它回查和列清单。
- **给用户看的内容只在对话里说，或放 Claude 文档，不写成 MD 文件**（2026-11-01 用户：“你以后不要给我 MD 文件了……咱们一条条确认吧”；11-21 又说：“少用md文档跟我沟通 除非是总结到哪儿我让你的时候”）：交付清单、目标、提速建议、方案说明、总结都在对话里列；要拍板的用选项一条条问。只有用户明确要求才写 MD。程序要读的记录（`反馈记录.md`、`03_成片/<项目名>.md`（定稿文案）、反馈单、项目复盘）照写，不拿来给用户审。项目收尾检查会提醒 `02_制作` 下多出来的清单类 MD。
- **起了审片台或发布了东西，就挂着等用户点“提交 AI”（审片台 v2 栏头主按钮）**（2026-11-22 用户定：“我一点发送给AI……然后他就开始改了”）：`workbench <项目文件夹> --wait` 放后台跑（Codex 前台加 `--wait-timeout 1500`）；它一退出就是用户发来了，按打印的清单逐项改、逐项 `--reply`，处理完再起一次。不要等用户在对话里说“看审片台”；`--wait` 断着页面会写“AI 离线”。见 [references/审片工作台.md](references/审片工作台.md)。
- **和用户说话用页面上的新叫法**（2026-11-25 用户定）：项目（不说“片子”）、首页四列 撰稿／初剪／精修／发布，栏目 文稿栏／口播精剪栏／配音试听栏／动画栏／审片栏／封面栏／发布栏，状态 待审阅／待提交／AI 处理中／✓ 已定稿，按钮 提交 AI／定稿，文稿栏定稿后 素材→开始制作，AI 在线／AI 离线。说法书面、简洁，不口语（如“在文稿栏撰写，完成后定稿”）。命令和数据里的名字不变（`--column 文案`、`写稿`、`口播试听`、`审核线`、`待你看`、`settled.写稿` 等照原样写），需要时写成“口播精剪栏（命令里叫 文案）”；达芬奇里的时间线仍叫“审核线”。完整对照表见 [references/审片工作台.md](references/审片工作台.md) 开头。用户说旧叫法时照样听得懂。
- **用户选中的字、点的那一帧只是定位，不是修改范围**（2026-11-22 用户定：“我选中这段字的时候，其实只是大意地给它标记为这个位置……它会根据我的语义来修改。如果它拿捏不准，它会来问我”）：先按意思判断范围（这一处／整句／上下句／全片同类／前后呼应），回写 `--note` 先写“我理解你的意思是……，所以改了这几处”，`--where` 标出改了哪几处；拿不准就不改，`--reply 编号 --status 问你` 回问，等用户在卡片上回答。不点哪改哪，也不借题改用户没说的。卡片上的意见同样。见 [references/审片工作台.md](references/审片工作台.md)「选中的字只是定位」。
- **每条意见都是一段对话**（2026-11-22 夜用户定）：用户随时在卡片最下面回复 AI（文字＋图），回复后那条回到待发送；读对话要照最新的回复改。要用户挑做法时用 `--options "A …|B …|C …"` 给按钮（审核线配 `--status 问你`），**选项写成用户一眼看懂的大白话**。见 [references/审片工作台.md](references/审片工作台.md)「每条意见都是一段对话」。
- **给用户看的都发到审片台，发了就接着做，不等他点**（2026-11-22 用户定“先做出来再改”）：样张、封面方向、试听等用 `workbench <项目文件夹> --publish … --draft`（拿不准的地方加 `--assume`，占位的加 `--placeholder`；样张出完自动发布）。用户在页面上点“可以”“选这个”“定稿”是他的事后确认，AI 用 `--list` 读；AI 不能替用户点（不用 curl、脚本模拟页面请求）。**整片导出、上传前必须有用户在审片台点的审片栏“定稿”**，别的都不用等。还没有项目目录（job.json）时，才按下一条发图片。
- **审核线建好后，别覆盖它正在用的文件，也别跳过修音**（2026-11-22 261122 反馈单 新3、新4）：`subs`、`pip`、`anim-assemble`、`nav` 等发现当前审核线引用着要覆盖的文件就停（先建新一版审核线，或 `--force`）；每个项目都 `voice-polish`（用户：“用达芬奇修音呗”），没修音 `check` 不过、`export` 停。细则见 [references/审核与导出.md](references/审核与导出.md)。
- **发图片、视频给用户看要点得开**（2026-11-21 用户：“你每次给我的这个都点不了”）：发文件卡片前先确认项目文件夹已加进本会话（没加就先加）；还点不开就用 `open` 在“预览”（视频用 QuickTime）里直接弹出来，并说清楚要看哪里、确认什么。
- **动画、建模、方案由 Claude 自己或 Claude 子助手做**（难的派 Opus 子助手），Codex 只用于生图（11-21 用户定）。**耗时处理默认并行**（渲染、自检截图、抽帧、转码、字幕整轨；达芬奇操作不并行），细则见 `studio/AGENTS.md`。
