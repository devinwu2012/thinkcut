# 动画（B 肉）怎么做：Blender 和 HyperFrames

新片子做镜头只有 Blender 和 HyperFrames 两种、按镜头选（2026-11-20 用户定，见 [动画风格.md](动画风格.md) 开头）。**第 6 节两种都要走的硬步骤**；第 7 节 Blender 出片模板；第 7b 节 HyperFrames 网页动画模板；第 8 节 派子助手做动画的派单模板（节号沿用原来的；原第 1–5 节讲老的代码动画，已下线，老片子重出见 历史做法.md）。

## 必守规则

1. 每个动画镜头的 `讲什么`、`口播要点`、`画面`、`运镜` 只写在片子目录 `分镜规格.json` 的镜头里（2026-11-13 起不另写 `镜头.json`），写法见 [分镜规格.md](分镜规格.md)「导演分镜」。没写口播要点的镜头不让渲。
2. **草图、样张不等用户点**（2026-11-22 用户定“先做出来再改”，程序不再拦；取代原来的“关系类先让用户选草图、整段渲染前要有样张确认”）：讲关系、对比、档位的镜头自己选一种最能讲清口播要点的画法；样张先自查，没问题就整段出片；样张照旧发到审片台“动画”栏，用户事后看、事后点。`出片.py` 会打印【初稿·未确认】列出哪些没确认，照做不停。见 [初稿模式.md](初稿模式.md)。
3. 标签至少停 2.5 秒、位置固定、不跟工具走，避开重点物体和小圆圈；**字放在目标点正上方，引线一条竖线直上直下、不拐弯；同一画面两个标签先后出现**（见 动画风格.md）；交审前标签逐帧自检必须 0 帧。
4. 音效、check 只认 `合成/动画清单.json` 里登记的那一版动画的事件表。
5. 谁来做动画、怎么派子助手：见第 8 节。

## 6. 两种动画（Blender、HyperFrames）都要走的硬步骤（2026-11-12 水电反馈；2026-11-22 起“等用户确认”的几条不再拦，见下一段）

**2026-11-22 用户定“先做出来再改”以后**：下面第 2、3、4、5 条里“等用户选、等用户点可以、给用户选了再定”的地方都不再等、程序也不再拦——AI 按自己的判断先做，做完用户在审片台事后看。第 1 条（写导演分镜、不用地图）、布局检查、第 6 条（标签逐帧自检 0 帧）照旧是硬的。第 2–5 条留着的是做法（草图怎么发、确认怎么记），用户事后点了照样记进确认记录。

出处：用户“你每次渲染的时间都很长，所以咱们一定要保证正确之后再渲染……样张都没问题了再渲染。”“这3个卡片没有讲清楚这个逻辑。”

1. **写导演分镜**（在 `分镜规格.json` 每个动画镜头里，2026-11-13 起和卡点写在同一份，Q045）：`讲什么`（关系/对比/档位/过程/结构/场景）、`口播要点`（对应的口播原话要点，一句一条）、`画面` 和 `运镜`（从哪到哪、几秒）；Blender、HyperFrames 工程的镜头再写 `"工程": "Blender_<名字>"` / `"工程": "HF_<名字>"`。没有要点的镜头不让渲。老片子工程里已有的 `镜头.json` 照样读；同一镜头两处都写了，以 `分镜规格.json` 为准。
   - **画面不用地图**（2026-11-21《装修最后那点细节》B01/B03 做了 3 版才定；用户：“不用地图这个表达方法行”“不要把地图画那么明显……能看清楚是个异地的感觉就行”）：标准地图要有审图号，改淡、裁切、放大、换色都算编辑、要重新送审，做动画几乎都要改。讲异地、多城市、离得多远，`画面` 写距离圈（HyperFrames 模板的 `共用/距离圈.js`，见第 7b 节），不画国界、省界。`画面`、`讲什么` 里写到 地图、国界、省界、省份、边界线、行政区 时（同一个半句里写了“不画/不用/无……”的不算），`beats` 会提醒，出样张、出片前程序会停下。这时先把上面这条规则讲给用户、建议距离圈；用户听完仍确认要地图，才记 `thinkcut_edit.py anim-confirm <片子目录> --kind 地图 --project <工程目录> --shots B01 --words "用户原话"` 放行（不用带图）。
2. **讲关系、对比、档位的镜头先出 2–3 张不同画法的逻辑草图静帧，发到审片台让用户选**（硬步骤，2026-11-22 用户定；可以用包装系统卡片、俯视图、HyperFrames 静帧画，不用先建模）。几张草图讲的是同一组口播要点，画法不同（比如俯视图／剖面／前后对比）。每张都要**逐条对照口播要点**写清画面里怎么表现，一起发布：
   `thinkcut_edit.py workbench <片子目录> --publish 动画 --kind 多选一 --anim 草图 --project <工程目录> --shots A23 --title "A23 草图三选一" --look "三种画法讲同一件事：…，选一种" --files 草图A.jpg,草图B.jpg,草图C.jpg --labels "A 俯视图,B 剖面,C 前后对比" --check "AC+AP 放床头柜后边=床头柜后墙上的 AP" --check "A:mesh 路由放衣柜里=衣柜俯视图里的 Mesh" --check "B:mesh 路由放衣柜里=衣柜剖面里的 Mesh" …`
   （`--check "要点=画面"` 对每张都算，`"A:要点=画面"` 只算 A；每张都要把口播要点对照全，不全发布不了。）用户在审片台点“选这个”就记进 `合成/确认记录.json`（和以前 `anim-confirm --kind 草图` 一样，带选中那张的图和对照），`--list` 读到选了哪张，按那张的画法出样张。没选定之前 `anim-gate` 拦着不让出样张。用户只在对话里说定了时，老办法照样有效：`anim-confirm --kind 草图 --files 那张图 --words "用户原话" --check …`。
   每条口播要点都要有一个 `--check`，少一条就不记（《水电》A23：AC+AP 和 mesh 位置放反，意思没跟口播）。
3. **出样张给用户确认**：Blender、HyperFrames 都是工程里的 `出片.py --样张 秒,秒`。出完程序**自动把样张发到审片台“动画”栏**（同一工程同一批镜头再出＝这一项的新版），“看哪里、确认什么”按分镜规格自动写好；审片台页面开着就不弹“预览”，没开照旧把拼图在“预览”里弹出、打印那段话（把这段原样转述给用户，并请用户在审片台上点）。用户在审片台点“可以”就记上确认（原话写“审片台：用户点了可以（时间）”），AI 用 `workbench <片子目录> --list` 读到后整段出片；用户写了要求就照改、再出样张（自动换新版），`--reply 编号 --note "改了什么"`。**样张、草图只认审片台上用户点的“可以”／“选这个”，对话里的原话不算**（2026-11-22 261122 反馈单 新1，Q177 复发：用户一句笼统的“导航文字还有封面你都一起都可以出”被当成了具体确认，后来用户推翻）：用户在对话里说可以，也请用户去审片台“动画”栏点一下；`anim-confirm --kind 样张/草图`（不带 `--免看`）只核对审片台有没有这次点击，没有就停下、不记。确认时记下动画代码的指纹；**之后改了场景、标签、布局、镜头起止或这个镜头的口播要点/画面，确认就作废**，要重出样张再问（`anim-gate` 会说缺什么）。
   - **授权免看**（2026-11-20 用户定，Q129）：只有用户自己事先说过“这条不用等我确认”（或同义的话）才能用，AI 才可以自己放行整段出片：`anim-confirm --kind 样张 --免看 --files 样张路径 --words "用户说的那句授权原话"`。仍要带样张图、写原话；记录里写明是“授权免看”，不是用户看过。能先出片，但**交审、交片时要把这些样张发给用户补看**：`check` 汇总和 `status` 都会列出还没补看的镜头；把样张发到审片台“动画”栏，用户点了“可以”就算补看完（2026-11-22 起对话里说的不算）。**导出前要么补看完，要么拿到用户同意照导的原话**（`export --未看样张用户同意 "原话"`，记进导出记录），否则 `export` 拦（11-20 定的是只提醒不拦，11-21 反馈单改成导出前拦）。用户没说过这句话，照旧必须等用户看过；草图、标签位置没有免看。普通确认的 `--words` 只写用户看过之后说的话，不能写“用户未逐张看”“没看”这类：用户没看就是免看，用 `--免看` 记；这样写的普通确认 check、export 一律当成用户没看过。
4. **标签位置**：拿不准的（程序判断：最好的位置也压东西、离目标太远、前几名分不出高低）会出 `样张/标签位置_<名>.jpg`（A/B/C）给用户选：`anim-confirm --kind 标签位置 --label 名字 --pick B --words "用户原话"`，选定的写成固定区域。
5. **整段渲染**（不管多大分辨率）：没有草图（关系类）、样张确认，或标签位置还拿不准，`出片.py` 不再停（2026-11-22），打印【初稿·未确认】照出；没写导演分镜、画面要用地图、布局检查没过才停。
6. **交审前标签逐帧自检**：Blender `出片.py` 整段渲完自动查（字压模型、字压字）；**必须 0 帧**，有就挪位置（Blender 只重新合成标签，不重渲）。HyperFrames 没有这一步，改用 `hyperframes check` 查字被盖住和对比度（第 7b 节）。
   - 盖了实拍的区间（分镜规格.json 的 `盖实拍`）标签不画（Blender、HyperFrames 自动藏）、自检不查：成片里看不见。
7. **出片登记、总装**：出完自动登记进 `合成/动画清单.json`（当前进成片的那一版、画面事件表）和 `合成/渲染尺寸.json`；`anim-assemble` 逐帧拼 `合成/B肉.mp4`，并逐镜头比对首/中/尾帧和动得最厉害的一帧（错一帧会报出来）。实拍镜头、图片镜头和“在动画镜头某一段盖实拍”写在 `分镜规格.json`（分镜规格.md「实拍和图片」），`anim-assemble` 自动做成片段（`合成/实拍镜头/`）、登记、拼进去，不手改这两个登记表。音效节拍、check 只读动画清单里登记的事件表（`anim.current_events`）；工程自己的 `事件.json` 写 `[{shot, t(成片秒), name}]`。
8. **预览分辨率**：审片轮 1080P、导出前才 `--4k`，规矩见 动画成片.md「准备」里“审片轮一律 1080P”那条。1080P 的出片总装时缩放进 4K 画布；`渲染尺寸.json` 里还有不是 100% 的，导出前会被拦（`anim.render_size_problems`，export 调用）。

## 7. Blender 出片模板（`blender-new`）

`python3 skill/thinkcut-edit/scripts/thinkcut_edit.py blender-new <片子目录> 通风` → `<片子目录>/Blender_通风/`。每期只改 `场景.py`、`布局.json`、`标签.json`（镜头说明写在 `分镜规格.json`，见第 6 节），其余原样用：

| 文件 | 作用 |
|---|---|
| `场景.py` | **每期重写**。按 `布局.json` 建模；`evaluate(镜头, t)` 由成片秒算出相机和动画（同一个 t 每次一样）；`points()` 给标签目标点和钉字的世界坐标点；`protected()` 给字不许压的重点物体；`events()` 给画面事件。模板是一个卫生间示例 |
| `布局.json` | 房间布局唯一数据源（俯视，米）：墙、门（合页、开向）、家具洁具（中心、尺寸、朝向、靠哪面墙）、淋浴间（范围、花洒位置）。场景不是房间的，在 `分镜规格.json` 该镜头写 `"不涉及布局": "原因"` |
| `布局检查.py` | **常识硬检查**：门开向不互撞、门口和门扇扫过的地方不被家具洁具挡、同一面墙上的洁具挨着（空超过 0.3 米要写 `gap_ok` 说明理由）、马桶前留 0.5 米、花洒在淋浴间一个方向的中线上、床沙发柜子马桶背面靠墙、不出房间不重叠不穿墙。不过就不让渲染；顺便出 `自查/布局俯视图.png`（也能当逻辑草图） |
| `标签.json` | 标签：文字、目标点、起止（卡点名或秒）；位置自动（默认在目标点正上方找，引线一条竖线；正上方放不下才到别处找并出位置样张问用户）/ `fixed.world`（钉在世界坐标，随镜头走，贴面写 `surface: true`）/ `fixed.region`（画面区域）。同一镜头两个标签起止错开，先后出现 |
| `出片.py` | 出片总控：`--冒烟`（一帧 25%，改完 `场景.py` 先跑它查脚本能不能跑）、`--样张 秒,秒`、整段（默认 1080P 审片版 / `--4k` 导出前定稿）；不写 `--shot` 时出 `分镜规格.json` 里 `工程` 写本工程的全部镜头。先过第 6 节的硬拦；**默认多进程**（1080P 及以下 8 个、4K 4 个，按 `渲染测速.json`，每个进程一段连续帧号）；逐帧图放这台 Mac 的临时目录（按代码指纹分目录，改了代码不会续用旧帧；没出成时留着、重跑接着渲，出片成功后自动删；本机空间不够会先停下说明），日志和每帧记录在工程 `缓存/`；标签用包装系统合成并逐帧自检；出到 `出片/<镜头>.mp4`（预览是 `<镜头>_预览50.mp4`）并登记 |
| `worker.py` | Blender 里跑的出帧进程，一次一段连续帧；PNG 先写 `.part` 再改名，断了重跑会续 |
| `渲染测速.json` | 这台机器开几个进程最快（M5 Max 实测：1080P 8 进程 78 帧/分、单进程 28；4K 4 进程到顶 21 帧/分）。换机器用《水电》`Blender_通风/渲染测速/测速.py` 重测 |

坑（《水电》实测）：Blender 5.2 无头渲染要 `--factory-startup`，用户配置、缓存、临时目录都指到这台 Mac 临时目录里这个镜头专用的 `运行环境/`（不动用户自己的 Blender 配置，渲完自动删）；场景要建 World，否则底色不对；`view_transform` 用 Standard，不然白模发灰；风格 4 工程透视的材质灯光可从《水电》`Blender_风格样张/render_styles.py` 复制。

## 7b. HyperFrames 网页动画模板（`hf-new`，2026-11-20）

HyperFrames 是用网页写画面、再逐帧出成视频的工具（开源，Apache-2.0，本地出片不收费）。用户在 2026-11-20 拿它和 Remotion 做了同样四道题后选定。考卷、两边成片和报告在 `$AI/环境/动画引擎选型_Remotion对HyperFrames/`，四道题的源码可以当范例看（清单、数据条、沿曲线运动的粒子、three.js 三维）。

**适合**：文字和数据动效、二维机制示意、轻量三维示意、要透明底的叠加动效。**不适合**：真实空间和真实光影（用 Blender）。

**怎么用**
1. `thinkcut_edit.py hf-new DIR 名字` → `DIR/HF_名字/`。在 `分镜规格.json` 给这个工程的镜头写 讲什么、口播要点、画面、运镜，并写 `"工程": "HF_名字"`，跑 `beats`。
2. 一个镜头一个文件：复制 `镜头/示例.html` 改名成 `镜头号.html`，只改“这个镜头的内容”和“时间轴”两处。
   - 内容都放在 `#design` 里，尺寸按设计稿像素写（3:4、9:16 设计稿宽 1080，16:9 宽 1920）。`#stage` 就是本片的画面区（导航条下面那块），位置由程序按本片版式摆，不要自己写 224、340 这类数。
   - 时间轴里的时间是“这个镜头里的第几秒”。要卡口播的字，在 `分镜规格.json` 的 anchors 定卡点，镜头里写 `THINKCUT.at('卡点名')`，口播时间变了不用回来改。
   - 卡点必须落在这个镜头的起止里（加上偏移也算），时间轴上的动作也不能排到镜头结尾以后（容差 1 帧）；越界时 `共用/基础.js` 直接报错（写清卡点名、卡点时间、镜头起止），`出片.py` 出样张、整段出片前先用 `hyperframes check` 查到就停、把原因显示出来，不会出一段错的片子。
   - 画幅、帧率、镜头时长都由 `出片.py` 从 `job.json`、`分镜.json` 读了填进去，镜头文件里保留 `__W__`、`__H__`、`__DUR__` 三个占位，不写死。
   - 配色和字体用 `共用/基础.css` 里的变量（`--bg --blue --red --green --dim`），不另起一套。要用 three.js：`import * as THREE from "./共用/three.module.min.js"`。
   - 名称标签用 `THINKCUT.label(tl, {x, y, text, from, to})`（x、y 是目标点的设计稿像素；from、to 可写 `THINKCUT.at('卡点')`）：字在目标点正上方、一条竖线，白字不加底、蓝圆环，和 Blender 标签一样；两个标签 from 错开、先后出现（示例.html 照此写）；这个镜头盖了实拍的那几段自动藏起来。不要自己画折线引线。
   - **几个镜头要共用同一段画法代码**（比如同一种柱子、同一套尺子；2026-11-24 初稿模式第二次实测，以前没写，子助手每个镜头抄一份）：写成 `共用/本片_名字.js`（文件名必须以 `本片_` 开头，放在这个 HF 工程的 `共用/` 里；`基础.js`、`基础.css`、`距离圈.js`、three、gsap 是模板自带的，**不改**）。每个用到的镜头文件在 `<script src="共用/基础.js"></script>` 后面加一行 `<script src="共用/本片_名字.js"></script>`，在时间轴里调它暴露出来的函数（脚本里把函数挂在 `window.本片 = {…}` 之类的全局上，需要时间轴就把 `tl` 当参数传进去，别在文件里自己建时间轴）。程序认 `共用/本片_*.js`：改了它，这个工程**全部镜头**的样张确认都作废、要重新确认（和改 `基础.js` 一样）；只被个别镜头用到也一样，所以只把真正共用的放进去，只有一个镜头用的留在镜头文件里。`hyperframes check` 照常查，每个镜头文件自己仍要有 `THINKCUT.pad(tl)` 那几行。
   - **距离圈**（2026-11-21 从《装修最后那点细节》B01/B03 收进模板）：讲异地、多城市、离得多远时用它，不画地图。镜头文件里在 `<script src="共用/基础.js"></script>` 后面加一行 `<script src="共用/距离圈.js"></script>`，时间轴里写：
     `const R = THINKCUT.distanceRing(tl, { center: "北京", cities: [{ name: "武汉", title: "武汉 · 灯光设计", at: THINKCUT.at("wuhan") }, { name: "广东", at: THINKCUT.at("guangdong") }] });`
     画出来是：圆心城市一个蓝点，外面几圈虚线距离圈（1000 km、2000 km……），城市按真实直线距离和方位摆（正北朝上）；到 `at` 那一刻从圆心飞出一条弧线和小飞机，落点亮起、出标签卡（大字默认城市名，小字默认“直线约 N km”）。城市表里有省会和常见城市，省名按省会算；表里没有的写 `{ name: "某地", lat: 纬度, lon: 经度 }`。位置自动排（城市和卡片都在画面区里、卡片互相不压、刻度字不压卡片）；出样张看了要调，再写 `origin`（圆心位置）、`scale`（每公里几个设计稿像素）、城市的 `side`（卡片放落点 right/left/below/above）、`bow`（弧线往哪边拱，1 或 -1），全部参数在 `距离圈.js` 开头。`R.pulse("武汉", 秒)` 让落点闪一下、卡片描蓝边；`R.cities` 里有每个城市的落点坐标，可以接着往上加自己的卡片（《装修最后那点细节》B03 的“去了几次”小飞机）。
3. 看效果：`python3 出片.py --预览 镜头号` 生成 `index.html`，再 `HYPERFRAMES_NO_TELEMETRY=1 hyperframes preview`；查问题用 `hyperframes check`（会查字被盖住、对比度不够、脚本报错）。它把镜头当整条片子看，所以“最后一句停留不到 2 秒”这类收尾提示对镜头不适用，其余的要处理。
4. 样张 → 确认 → 出片，和 Blender 同一套硬步骤（第 6 节）：`python3 出片.py --样张 成片秒,成片秒 --shot 镜头号`（自动发到审片台）→ 用户在审片台点“可以”（`--list` 读到；用户只在对话里说可以时 `anim-confirm --kind 样张 --project <HF_名字 的完整路径> …`）→ `python3 出片.py --shot 镜头号`（默认 1080P 审片版，出成 `出片/镜头号_预览50.mp4`；导出前加 `--4k` 出 4K `出片/镜头号.mp4`）→ `anim-assemble`。
   - 样张确认按镜头算：每个镜头的确认只认它自己的 `镜头/镜头号.html`（加上 `共用/` 和镜头起止、口播要点），改了一个镜头只要重新确认这一个；改了 `共用/` 里的样式脚本，全部镜头都要重新确认。
   - 每出完一个镜头，程序核对帧数和尺寸，对了马上登记这一个（登记的文件和 scale 就是实际出的那个，预览如实写 50）；中途某个镜头失败，前面已出好的照样登记着，和磁盘上的文件一致。
   - `index.html` 是各镜头共用的生成文件，从生成到这个镜头出完/截完都拿着工程里 `index.html.lock` 这把锁（`--预览` 写完就放），同时开两个出片进程会排队等，不会互相覆盖。
   - 样张：一个镜头要的几个时刻开一次浏览器截完（`snapshot --at` 多个时刻）。镜头之间不同时出片：2026-11-22 试验田实测，HyperFrames 几个镜头同时出时显卡截图会变（B04 4K 有 47 帧和单独出不一样），所以照旧一个一个出。
5. 要透明底：`python3 出片.py --shot 镜头号 --透明`，另出 `出片/镜头号_透明.mov`（ProRes 4444；预览是 `镜头号_预览50_透明.mov`），不登记进成片，叠到实拍上用。
6. 音效节拍要卡画面事件时：HyperFrames 工程不会自动产生 `事件.json`，由做镜头的人在工程里自己维护 `事件.json`，写法同 Blender 工程（`[{shot, t(成片秒), name}]`，第 6 节第 7 步），出片登记时一起记进动画清单。

**要知道的**
- 模板和选型都在 HyperFrames 0.9.39 上验证；`doctor` 会显示这台装的版本，不是 0.9.39 时先出一张样张看对不对。安装：`npm install -g hyperframes@0.9.39`。
- 出片脚本每条命令都带 `HYPERFRAMES_NO_TELEMETRY=1`（不上报使用数据，不改这台 Mac 的设置）。自己手敲 `hyperframes` 命令时也带上。
- 同一台 Mac 上同一帧重出完全一样（选型时实测）；换一台 Mac 是否逐像素一样没验证，所以同一条片子的 HyperFrames 镜头在同一台上出完。
- 不用它的云端渲染、上传分享、Pro 功能（要登录别家账号、可能收费）；只在本地出片。
- `index.html`、`index.html.lock`、`样张/`、`出片/`、`缓存/` 是生成的，可以删了重出；`镜头/`、`共用/` 才是源文件。

## 8. 派子助手做动画的派单模板

动画不交给 Codex（Codex 只生图，规矩见 SKILL.md「所有步骤都遵守」）。《别墅装灯》第 17 轮由 Opus 子助手改源码、自己出样张自查，一次通过。分工（中控分工）：**Claude 写导演分镜和派单、做最终验收；难的镜头（建模、光影逻辑、改源码）派 Opus 子助手，常规小改 Claude 自己做或派 Sonnet 子助手；子助手改完自己出样张看，看着不对接着改，再交回**。派单照这个写（直接写进派子助手的话里，不另存文件）：

```
# <片名> <镜头> 第 N 轮
## 目标（口播原话要点，逐条）    ← 从 分镜规格.json 这个镜头的“口播要点”抄，画面必须逐条对上
## 导演分镜                      ← 分镜规格.json 里的运镜、画面和 分镜.json 的卡点；不自己改机位和节奏
## 用户原话和截图                ← 这一轮用户说了什么（原话）、截图路径
## 只改这些文件                  ← 场景.py / 标签.json（HyperFrames：镜头/<镜头>.html）；布局.json 由 Claude 改
## 不要做                        ← 不改 出片.py/worker.py/布局检查.py/共用/；不加标签底；不自己整段渲染、不记确认
## 自查（子助手自己做）          ← Blender：python3 布局检查.py → python3 出片.py --冒烟 → 出片.py --样张 秒,秒；HyperFrames：出片.py --预览 镜头号 后 hyperframes check、出片.py --样张。出样张的命令前加 THINKCUT_SELF_CHECK=1（自查：不发到审片台、不在用户的 Mac 上弹窗）。逐张看样张，对照口播要点和物理常识（动画成片.md 第 5 步）
## 交回                          ← 改了哪些文件哪几行、样张路径、担心的地方；停下必须写原因
```
