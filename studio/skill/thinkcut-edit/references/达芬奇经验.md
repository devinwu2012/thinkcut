# 达芬奇脚本：实测的坑与改后对齐

## 连接与工程

- **色彩管理＝输出标准**（2026-11-28 用户定：“工程开色彩管理”“最终都不需要 HDR”“按照 iPhone 看起来比较好的标准”）：新建工程自动设，已有工程 `project.py resolve-color <项目>`。设定在 `core/engine/broll/live/placement.py` 的 `COLOR_MANAGED`：DaVinci YRGB Color Managed（自定义）、未标记素材当 Rec.709 Gamma 2.4、时间线 Rec.709 Gamma 2.4、工作亮度 SDR 100、输入色调映射 DaVinci、输出 Rec.709-A。前端拍什么都行，达芬奇按素材标记认（iPhone HDR 认成 Rec.2100 HLG）；成片 SDR 709、H.265。实测（达芬奇 21.1）：只开自动管理时默认输出 Rec.709 (Scene)、工作亮度 HDR 1000，HDR 素材严重过曝；输出 Rec.709 Gamma 2.4 的成片在苹果解码下偏亮发灰，Rec.709-A 对比更接近原意；普通 Rec.709 口播开色彩管理前后时间线画面一样。Rec.709-A 只能在自定义模式设。建议在达芬奇 偏好设置 → 常规 打开“检视器使用 Mac 显示器色彩配置文件”，剪辑时看到的和 iPhone 上一致。
- **59.94 的 iPhone 原片直接放进 29.97 时间线**（2026-11-28 实测）：达芬奇把这类片子读成 60 帧；入点给源帧号，结束帧按 达芬奇读到的帧率÷时间线帧率 往上取整，帧数、入点读回都准（`broll/live/resolve_adapter.py append_clip`）。照片时长接口设不了（固定 5 秒，媒体池的 Duration 也改不了），照片照旧转成衍生片段。

- 用 DaVinciResolveScript 直连（`scripts/thinkcut/resolve.py`）。**不要用达芬奇 MCP 做时间线写操作**：它会自动复制 `_archived_vNN` 时间线，还会把当前媒体夹切到 Archive。（2026-11-28 起后台 AI 能经 ThinkCut 护栏用达芬奇 MCP 看和小改，规矩见 审片工作台.md「AI 引擎」；程序自己的写操作仍走直连。）
- 脚本模块会把 locale 改成 C，所以 `thinkcut_edit.py` 启动时自动以 UTF-8 模式重启自己。自己写脚本时要加 `PYTHONUTF8=1`。
- 工程在片子自己的项目库（2026-10-29 起，库名=项目文件夹名，位置 `02_制作/达芬奇工程`）；达芬奇刚打开时默认进的可能是局域网协作库（不是片子自己的，不用）。`project()` 先找片子自己的库，有就只在里面找；老片子没有这个库时才挨个库找。找到后记进 job.json 的 `resolve_db`。切换库和工程之前，会先保存当前开着的工程。
- 外部脚本要在 偏好设置 → 系统 → 常规 → “外部脚本使用”里设为“本地”。

## 放片段

- `AppendToTimeline` 的 `endFrame` 实测是**不含**的：`startFrame 0, endFrame 24` 放上去正好 24 帧。
- 一次批量导入几十个 4K ProRes 4444 小片，达芬奇会闪退。所以字幕做成一条“整轨”，只导入一次，再按每条起止切开放。
- PNG 静帧放到时间线上会被当成 1 帧序列，不要用 PNG 当字幕片段，要转成指定帧数的 .mov。文件名里也不要带数字，否则会被当成图片序列，所以字幕文件用 `字幕_aaa` 这样的字母编号。
- 导入 yuvj420p 的大文件时闪退过：先转成标准 yuv420p 再导。B 肉出片已经是 yuv420p。
- **删掉再放回的片段会丢检查器设置**（缩放、位置、裁切等）。重放之后要对照原片段的 `GetProperty()` 全部补回，再抽帧看。`subfix` 已经这样做了。
- 导航条以前是一条 2160×320 的条子，靠 Tilt 移到顶上。Tilt 的数值不直观（≈10757.6），重放时丢过一次，结果整屏铺满。所以现在把导航条转成**整帧透明片**，放上去就在正确的位置，不需要任何变换。
- `DeleteClips(items, False)` 删除时不波纹，后面的片段不动。
- 音画要一起剪时，重放之后用 `SetClipsLinked` 重新链接。
- 中文界面下 Type 显示“视频 + 音频”，标记颜色没有 Teal，`AnchorPoint` 用 SetProperty 设不上（总是返回 False）。

## 片段变速（口播 1.2 倍速，2026-11-27 试验田实测，达芬奇 21.1.2）

用户 2026-11-27：“直接可以用达芬奇里1.2倍速就完了呗”。剪口播交付时就是这样放原片的（`core/engine/src/import_mvp_delivery.py`、换算在 `speed_map.py`）。
- 21.1 起 `TimelineItem.SetSpeed({'Percentage': 120, 'PitchCorrection': True, 'RippleTimeline': False})` 能设速度（和界面上 Command+R 改速度是同一个设置），`GetSpeed()` 读回；官方 README.txt 里没写，接口说明在 MCP 的 `docs/reference/DaVinciResolveScript.pyi`。21.1 以前没有，`SetProperty('Speed', …)` 设不上。
- **设速度时片段在时间线上的长度不变，来源往后多取**（不波纹时）：放 599 帧、设 120% 后还是 599 帧，来源从第 300 帧变成到第 1019 帧。所以要先按“加速后的长度”放，再设速度；不是放完原长再缩短。
- 连着的声音片段自动跟着变速；导出 DRT 再导入，速度保留（交付写字幕那一步不会丢）。
- 30 帧原片放进 29.97 时间线是按真实时间换算的：放 n 个原片帧，时间线上占 floor(n × 29.97/30) 帧（600 → 599，1001 → 1000）；起点也会对到时间线的帧格上，读回的来源起点可能差 1 个原片帧。设了速度后 `GetLeftOffset()` 是按时间线帧算的（来源第 300 帧、120% → 249），核对来源位置用 `GetSourceStartFrame()`。
- 渲染比对：声音和“原片补齐开头再 ffmpeg atempo 1.2”差 2–15 毫秒；画面和声音差 -18～+4 毫秒，在原片 10、50、100 秒处不随时间变大（iPhone 标称 30、实际 29.993 帧的可变帧率原片也一样）；手机原片声音晚开始 49 毫秒，达芬奇按这段空白放，对得上。
- 变调校正（PitchCorrection）的音质没有逐句听过；声音最后都经 `voice-polish` 整条修。
- HLG/PQ（HDR）原片：以前 speed_voice.py 转码时自动套“苹果显示曲线”让颜色和 Mac 上看一致，现在原片直接进达芬奇，没有这一步，HDR 原片的颜色要在达芬奇里看一眼（不套 LUT 的规矩不变）。

## 核对

- **音频轨开关只认当前时间线**（2026-11-27 试验田实测，21.1.2）：对不是当前的时间线调 `GetIsTrackEnabled('audio', n)`，读回来的是当前时间线第 n 条音频轨的开关（261114 里所有时间线的“音频 1”都读成关，其实只有当前的修音时间线关了）。核对哪条时间线的音轨开关，先 `SetCurrentTimeline` 切过去再读。

- 写完都要 保存 → 关闭工程 → 重开 → 读回，只看重开后的数据。
- 关键帧用 `Project.ExportCurrentFrameAsStill(路径.png)` 从达芬奇直接导出，导出的画面包含导航条和字幕，比自己拼图可靠。
- `snap` 记录每条轨上每个片段的起止、源起点、音量和主要检查器设置。改动前后各拍一次再 `diff`，就能看清改了什么。

## 改后对齐（用户在审核线上手改之后）

先 `snap`，再和 `快照/<审核线>_建好时.json` 做 `diff`。烟道那条的实例：

- **现象**：用户在开头一句话里剪掉 3 帧停顿，但只剪了声音，没剪画面。后面的动画、字幕、音效、导航，用户已经整体前移了 3 帧。
- **后果**：
  - 剪口之后到下一刀之间，口型比声音慢 3 帧。
  - 剪口处留了 1 帧空白。
  - 开头动画多盖了 3 帧口播画面。
  - 导航条最后少 1 帧。
- **处理**：
  - 画面和声音在同一个位置都去掉同样的 3 帧，前后两段接上，不留空，并重新链接。
  - 跨过剪口的动画镜头和导航条一起收短 3 帧。
  - 已经整体前移的轨道不动。
- **核对**：
  - 把“建好时”的帧号换算到新位置（剪口之后的减 3），逐轨比对：动画、字幕、音效都还卡在原来的词上，音量没变。
  - 抽几张关键帧，和改前逐像素比较。

原则：

- 先诊断，把用户改了什么、出了什么问题用大白话说清，再修。
- 只修被这次改动影响的片段，用户手调过的东西不重置。
- 修完照样 保存 → 关闭 → 重开 → 读回，并抽帧核对。


## 返修换片与音量（2026-10-24《精装房为什么会臭气熏天》）

- **换动画**：动画轨所有片段共用一个媒体，返修后出新文件（带轮次，如 `B肉_小圆圈_r17.mp4`），对媒体池里这个片段 `ReplaceClip`，片段位置和用户的剪辑都不动；保存 → 关闭 → 重开 → 读回文件路径和片段数，再确认花字轨没变。
- **打标记**：改过的镜头起点加绿色时间线标记，名称“改：镜头 一句话”，duration 覆盖这个镜头；下一轮先删掉上一轮的绿色“改：”标记再加，用户自己的标记不动。
- **改音效**：按（时间线位置，文件名）对上音效表逐个改；当前音量和上一版 AI 写入值不同的视为用户手调，不动并报告。新增的放进空闲的“音效”轨，有重叠换下一条。
- **原生平衡**：Studio 21.1 起有 `Timeline.NormalizeAudioLevel(items, {normalizationMode, targetLevel | targetLoudness, setLevelMode})`，模式名用 `GetNormalizeAudioModes()` 看。`export` 默认就用它平衡（`--no-balance` 不平衡）。界面里的“AI 音频助手”脚本调不了。
- 脚本写完、保存成功后退出时偶尔报 139（段错误），是达芬奇脚本库退出时的问题，写入不受影响；照样另开一次读回确认。

## 写入锁、渲染设置、人声隔离（2026-11-21《别墅装灯前》）

- **一次只让一个命令写达芬奇**：两个会话同时重建审核线、渲小样，达芬奇卡死在“渲染中”，退出也没用，只能强制结束。现在所有写达芬奇的命令共用一把写入锁：本机文件 `~/.cache/ai-talking-head-edit/resolve-write.lock`（和 口播剪辑 的 B-roll/花字写入是同一把），用 `fcntl.flock` 加独占锁、拿不到不等直接停；进程退出（做完、崩溃、被杀）系统自动放锁。锁文件里写一行 JSON `{"片子目录", "命令", "进程号", "开始时间"}` 给第二个人看（口播剪辑 只写进程号也认）。锁文件不要删（删了会出现两把锁）。别的仓库写达芬奇时照这个做：口播自动剪辑里是 `resolve.lock(job, 命令)`，常驻的服务（审片工作台）做一下就 `resolve.unlock()`。只读查询（读时间线、快照）不拿锁。
- **渲染前先载预设**：脚本渲染的设置会留在工程里（比如只导音频、改了编码），下一次渲染照用，小样就只出声音。所有脚本渲染先 `project.LoadRenderPreset('H.264 Master')` 再逐项 `SetRenderSettings`（`resolve.fresh_render`）。
- **人声隔离可以脚本开**：音频片段属性 `AudioVoiceIsolationEnabled`（True/False）和 `AudioVoiceIsolationAmount`（0–100，本片 70）。`Timeline.SetTrackEnable('audio', n, False)` 对音频轨有效（对视频轨无效）。`voice-polish` 就是靠这两条做的。
