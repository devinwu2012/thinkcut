# 初稿模式：接到新项目任务，五项一口气做成初稿，用户边看边改

2026-11-22 用户定。原话：“每次我一发这个新的任务的时候，他就直接这五项一起做。我当时给了他什么资料，他就在这个资料基础上直接做出来，按照AI的想法直接做就行了，不用来问我，等做完了我边看边改，而不是说一顿问我再去做……只有一个口播的文案，都没有这个A-roll，那它就机器生成人声做上去得了……只有一个A-roll……没有这个素材什么的，它就自己生成，或者用……生图先做上……我有了之后我再替换，我再跟他一说就OK了。所以我需要它像一个剪辑师一样，先给我做出来，等我剪辑播时再来改，而不是每次都要问我什么的。”

**这份说明比各步骤说明里“先问、先确认”的旧写法新，冲突时以这里为准。**

## 四条规矩

1. **不问，先做。** 接到新项目任务，按用户给的资料把五项——口播剪辑、动画和画面、审核线（含导航条、花字、音效、字幕）、封面、上传文案——全部做成初稿，发到审片台，然后挂 `workbench <项目文件夹> --wait` 等用户边看边改。中间不停下来等用户确认、选择、过目。
2. **拿不准不问，写明假设。** 按最合理的做，在审片台对应卡片上用 `--assume "…"` 写“我是这么假设的：……”（页面上显示这一行）。用户提了意见之后，AI 才可以回问（审核线 `--reply 编号 --status 问你`，其余栏 `--reply 编号 --note "问题" --options …`）。
3. **缺的东西用占位，标清楚。** 没有口播录像 → 机器配音；缺画面 → 生成占位图。占位在审片台上有“占位”记号和一行说明，用户给了真素材说一声就换（做法见下）。
4. **只留两道闸，AI 不能替用户过。** ① 整片 4K 导出：用户在审片台审片栏点过“定稿”、之后内容没变，`export` 才导（对话里转述的“可以了”不算，`--user-ok` 只当备注）。② 上传：`upload` 查成片是不是用户确认后导出的；存的只是蚁小二内部草稿，正式发布只能用户自己在客户端点。

**仍然要先问的**（和“先做”不冲突）：删用户的数据、对外发消息、付款或明显超出平常的花费、改权限、动用户手改过的东西（用户手改的就是定稿）、可能重复计费的重试（`--retry-uncertain`）。这类一开始就先查、先说，别做到一半才停。

**达芬奇不在“先问”里：开没开、开着什么都不问，程序自己备好**（2026-11-23 初稿模式实测后定；取代原来“开着别的工程要切走先问”“没有项目库要用户先退出达芬奇”）：
- 口播交付 `deliver` 会自动先跑 `project.py resolve-open <项目>`：达芬奇没开就登记这个项目的项目库并打开达芬奇；开着、库列表里有这个项目的库就切过去；没有（达芬奇开着时建的新项目登记不了库——达芬奇的脚本接口不能新建库）就**借用当前开着的磁盘库**，在里面新建和项目文件夹同名的工程（29.97，缓存和调色静帧在项目文件夹）。借用记在 `项目.json`，存档后再迁回自己的库。**不要让用户退出达芬奇。**
- 要切走用户开着的工程时：程序先保存它（保存失败、正在渲染就停下不切），把原来的库、工程、时间线记进 `<项目>/02_制作/达芬奇切换记录.json`。做完**停在新项目的审核线上**，不切回去。
- 最后汇报时说一句：“达芬奇从《X》切到了这个项目，要回去说一声”（`status` 的【初稿五项】末尾会提醒，照着说）。工程借用了别的库也说一句。
- 存档（`project.py archive`）不属于初稿：它开着别的工程时仍按 thinkcut-project 说明处理（`--switch`，做完会切回）。

## 什么时候做动画，什么时候用占位图

2026-11-23 初稿模式实测后定（那条讲“开关离地一米三、插座离台面三十公分”，7 个镜头却全用了占位图，不合格）。用户要的是“像一个剪辑师一样”：

- **做动画**：讲**结构、尺寸、位置、原理、步骤、对错对比**的镜头——有数字和单位（一米三、三十公分）、离地／离墙／间距、第几步、先…再…、正确和错误做法、为什么会这样。只有文案、没有任何素材时这类镜头照样做动画（HyperFrames 讲数字、示意、对比；Blender 讲空间结构），不因为“反正是初稿”改用图。
- **用占位图**：只有需要**真实场景、真实质感、真人**的镜头——开场的生活场景、装好之后的样子、材料的质感、人在用。先查过素材库（`library.py find` 明说“素材库里没有合适的”就是没有，不要拿只对上虚词的结果凑）。
- **机器配音的项目里“本该露脸”的句子**（自我介绍、结尾引导关注）：写 `"文字卡": ["我是<IP 名>", "关注我"]`（一到三行，写什么话按这个 IP 规矩的「品牌和口吻」，`beats` 自动画一张深底白字的中性字卡），不要为它生成一张不相干的图。
- `beats` 和 `status` 会提醒“讲到尺寸位置却写了占位图”的镜头和“全片没有一个动画镜头”。确实整条都不需要动画时，把原因写成全片假设：`python3 "$S" assume DIR "没做动画，因为……"`。

**全是动画（或占位图、文字卡）的项目也要有花字**（2026-11-24 初稿模式第二次实测：38 秒的项目只出了 1 个花字。原因不在程序，是“动画镜头里已有大字就不再叠花字”被读成了“动画镜头一概不配”，而且 koubo、leader 只能用在露脸或实拍上）：花字选点不依赖露脸或实拍，按包装系统的数量规矩（大约每 20–30 秒一个，`check` 按每 30 秒至少一个提醒）来选——

- **全动画的项目只用这四种**：`keywords`（并列列举）、`number`（关键数字）、`note`（注意事项、出处）、`statement`（主题句，全片最多 2 个）；`koubo`（口播大字）、`leader`（引线标注）、人挡字都要露脸或实拍，不要用。位置按包装系统的“不挡脸、不压动画主体”放，`check` 的几何遮挡会查。
- 照常守 3 秒间隔、同一时刻最多 1 个；`check` 还是报“花字偏少”就写进全片假设（`assume`），说明哪几处没法配、为什么。

**AI 自己能做的检查**（2026-11-23：说明以前写“交审前整条播一遍”，AI 做不到）：`check`、`subs-check` 的总览图、占位图总览、每条花字和下划线出现后抽一帧看（`stills DIR --name <审核线名> --frames 帧号,帧号`（帧号＝秒×帧率；审核线名看 `status`）；`subs-check` 的总览现在会把花字也叠上（2026-11-24 初稿模式第二次实测起；要先出花字表再跑），花字压没压人脸、压没压字先看总览，拿不准再用这一步抽帧）、动画样张自查。做不到真的从头播一遍听，汇报里照实写“没有真听”。

**随手记反馈用命令，不手写时间**（2026-11-23：AI 手写的时间是估的，比电脑的钟晚了半小时）：`python3 "$S" note DIR --step 环节 --who 用户|AI自查|工具拦下 --what "发生了什么" --how "怎么处理"`，时间自动用电脑的钟。

## 发布到审片台时怎么标

```
python3 "$S" workbench DIR --publish 栏目 … [--draft] [--placeholder] [--assume "我是这么假设的……"]
```

- `--draft`：这一版是没问用户、按 AI 判断做的初稿，卡片上挂灰色小记号“初稿”。初稿阶段发的卡片都带。
- `--placeholder`：这一项里有占位的东西（机器配音、生成图），挂“占位”。
- `--assume`：拿不准、没问、按最合理的做了的地方，一两句大白话，例如 `--assume "你没给现场照片，我按常见的客厅画的；灯的型号口播没说，没写字"`。
- 这三样只跟着那一版；换新版（`--reply 编号 --files …`）就没有了。它们不是状态：页面上的状态还是 4 个（待审阅、待提交、AI 处理中、已定稿）。
- **不属于哪张卡片的全片假设**（画幅没说按 3:4满屏、没做动画的原因）：`python3 "$S" assume DIR "……"`（记进 `job.json`，显示在审片栏头下面，和“占位：…”排在一起；不带文字只列出，`--clear` 清空）。
- 样张由 `出片.py --样张` 自动发布，不带这些记号；需要说明假设时再用 `--reply 编号 --note "我是这么假设的：…"` 补一句。

## 占位怎么换

- **机器配音 → 真口播**：新剪一条（真口播的长短和节奏不一样，不能 `replace-source`）。`prepare --video <真口播原片>` → 选重录 → `finish` → 气口精修 → `corrections --done` → `deliver`；然后 `init DIR --force --aroll <新剪口播工程>`（job.json 里的 `placeholder` 自动没了；2026-11-27 起开审片台时自动做，手动跑也行）→ `words` → `beats`（卡点按词找，自动落到新口播的时间）→ 分镜里加回露脸段和小圆圈 → 重出受影响的动画 → `anim-assemble` → `aroll-render` → `pip` → `sfx` → `subs` → 导航 → `review`（新一版审核线）→ `voice-polish`。
- **占位图 → 真素材**：把那个镜头的 `"占位图"` 删掉，写 `"实拍": 路径`（或 `"图片": 路径`）→ `beats` → `anim-assemble` → `pip` → `review`。占位图文件留着不删。只换其中几个镜头就只改那几个。
- 换完审片台上“占位：…”那一行自动少掉（它是从 `job.json` 的 `placeholder` 和 `分镜规格.json` 的「占位图」现算的，不另记清单）。
