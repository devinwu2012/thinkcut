# 花字音效

## 必守规则

1. **用户改过的素材整项不再改**（2026-10-17 用户：“只要是我改过的素材都不要再改了。”）。写入前读 `口播剪辑/AGENTS.md`「用户手工定稿保护」全文照做；本文件的重建、小修、清理都受它约束。
2. 写入前自己核对清楚改哪个工程、哪条主时间线、处理哪些标记；**用户交来新项目任务或说了“加花字／音效”就是授权，演练没问题直接 `--apply`，不再停下来等同意**（2026-11-22 用户定“先做出来再改”；取代原来的“用户同意后才 `--apply`”），做完告诉用户动了哪里。删除、移轨、动到用户手改的东西照旧先问。写入命令都要 `--project`、`--timeline`，默认只演练。
3. 花字用剪辑页**原生 Text+ 独立标题片段**直接放主线，不做装 Fusion 文字节点的复合片段；只有跟踪、抠图、背景模糊这类效果才用 Fusion。
4. 样式只用包装系统：苹方 SC 中粗白字、不加底、柔和投影，颜色只用白和 `#64A9E8`；Text+ 默认 `brand_label`。计划里要强调色写 `style.color="accent"`，计划校验和 build 不接受别的文字颜色（用户在达芬奇里手改的不受此限）。
5. 音效对准画面上发生的那一下；同类事件全片同一声音；一个镜头 2 秒内不超过两声。后两条程序会查，违规就列出来等用户决定（口径见 [计划与安全.md](references/计划与安全.md)「音效规矩」）。
6. 每轮都重新读当前主线全部标记，逐个对照；缺失、原文改变、未覆盖的标记必须报告；没写进工程的不说完成。
7. 写入一律 `PYTHONUTF8=1` 的 DaVinciResolveScript 直连，不用 MCP 写，不自动渲染；先由用户打开目标工程，不切换数据库、不打开其他工程。
8. 工具成功、参数通过、用户看过/听过认可，三件事分开汇报；失败保留现场，不自动重跑。

## 风格与分工

- 先读 [风格手册](references/风格手册.md)。分叉前带来的别人的花字规则全部去掉（2026-10-24 用户定，从两条项目提取）。
- 讲解文字靠字幕和动画标签，没有用户要求不加口播花字；实拍里点名部件或品牌时做跟随标签，按手册的尺寸和做法。
- 包装系统样式取代蓝底 `#2F7BFF`、冬青黑体、对比标签橙底 `#FF6F00`（2026-11-12 用户定）。实拍画面太花、白字挪到哪都看不清时才用 `brand_label_dark`（深色半透明胶囊底）；两种都已在达芬奇实测校准（居中单行）。
- 分工：达芬奇 Text+ 花字＝要在达芬奇里能改字、要跟随物体的标签和对比标签；包装系统（`$AI/口播自动剪辑/skill/thinkcut-edit/assets/包装系统/`）＝数字、关键词、口播大字、金句、卡片等出好透明片放花字轨的。

## 制作方式

- 默认用**剪辑页 → 特效库 → 工具箱 → 标题**里的 Text+／文本或指定标题预设，在剪辑页检查器修改（2026-10-16 用户定）。Text+、Text、中文“文本”都按剪辑页标题理解：以独立标题片段、不用打开复合片段、检查器能改字为准。Text+ 流程不授权载体视频、复合片段或手搭文字节点链。Fusion 的做法见 [写入与交付.md](references/写入与交付.md)「使用 Fusion 时」。
- **默认淡入淡出**（2026-11-12 用户看对比片后定：“用淡入淡出”，取代 10-16 的“默认静态”）：0.40 秒缓出淡入＋上移 28px（4K 竖版）、0.30 秒缓入淡出，只做透明度和位移，不做模糊。程序自动加（`fx_styles.json` 的 `motion`），计划不用写；用户说某条要静态才写 `style.static=true`。
  - 弹出、缩放、跟踪、逐字出现等其他动作只在用户指定的段落做，不推广。
  - 连续状态清单只在第一状态淡入、最后状态淡出，中间切换不闪。
  - 改了起止的花字，淡出关键帧不会跟着挪，要按新起止重做（小修不自动处理）。
- **剪辑页控件必须真实可用**：脚本改标题时保留原生模板信息，包括 Text+ 合成的 `CustomData.TEMPLATE_ID = "Text+"`；只改片段类型或工具名不够，丢了会让检查器只剩标题栏、用户被迫进 Fusion。交付前在剪辑页实际选中一条，确认检查器显示文本框、字体和字号，位置可在剪辑页调；其余同类只做模板信息与写入确认，不抽帧。
- 用户说自己审画面时，只做内容、起止、写入及保存的必要确认后汇报；不自动抽帧、重开工程、连续播放复检或生成审片线。完整验收和审片流程只在用户要求时做。

## 音效

- 音效对准画面上发生的那一下（出现、划线、划掉、变色）；同一类事件全片用同一个声音（`sfx_favorites.json` 的 usage 写了用在哪）（2026-11-01《别墅地下室防水》用户：“至少得跟画面呼应上”）。
- 库里没有合适的：先说清“这个动作像什么声音”，下候选，做“放在真实画面＋口播上”的试听片让用户挑；选定的入库、写来源说明、登记 usage。
- 同步以真实波形的目标瞬态对齐文字实际出现帧，不对齐素材左边界；素材可提前起；多个尖峰先辨认承担同步的那一下（2026-10-16 用户纠正）。用户要求逐帧对齐时，不套默认提前 1 帧、不只用静音检测当验收，按 [音效.md](references/音效.md) 的波形核对做。

## 标准用法

1. 用户在精修时间线上打标记，或直接说“帮我加花字”。AI 读标记、字幕和截图，按风格手册写计划（[计划与安全.md](references/计划与安全.md)）。
2. 核对清楚改哪个工程、哪条时间线、处理哪几处，演练没问题就 `build --apply`（不用等用户同意，见必守规则 2）：
   - 花字以独立原生 Text+ 放在现有画面之上最低的一两条可用轨，跳过锁定、停用或被占用的轨。
   - 音效从 A3 起复用一两条音效轨，A2 留给 B-roll 原声。
   - 用户当次指定优先，计划可写 track 覆盖；没有可用轨才新建「花字/音效」命名轨。
3. 交付前按 cleanup 演练清理本程序过程线，再交付主线位置，交付清单在对话里列（不写成 MD 文件，2026-11-21 用户定），由用户审画面、节奏和试听。只有用户要求才另建审片线；审片线上不改字。
4. 有修改：用户直接点主线上的花字在检查器改字、大小、位置；或 AI 更新计划，默认 auto 模式识别小修。整批新做才用 batch；手调保留。

已知限制：
- 空文字的原因还没查明：整批新做的 build 保留“保存→重开→文字不空”检查，小修不重开。
- 对比标签在那段没说到对应词时，按画面节奏出现。
- 抠像较慢（约 30 秒处理 1 秒画面），只给被挡的字做。
- 两台 Mac 协作还没实测。
- build 只支持特效库 Text+ 标题。用户要普通“文本”时用剪辑页原生文本的可用操作，不用复合片段或自建 Fusion 合成代替。

## 工作目录

- 工作台＝本文件真实路径往上两级。
- 标准项目（项目根有 `项目.json` 和 `01_原始素材`）默认放 `<项目根>/02_制作/花字音效/<批次>/`；批次默认是计划文件名，可用 `--batch` 指定。不是标准项目时用 `<片名>_AI剪辑/花字音效/`。已有工作目录照常用，不搬家；`--work-dir` 明确指定，`--project-dir` 帮助定位项目根。
