# 封面

下面是版式和流程（程序自带、每个 IP 通用）。**每个 IP 的封面风格**——颜色、字体、压窄这些数在配置档 `封面.*`（程序按 DIR 往上找 项目.json 的 ip 自动换，不在项目里时用默认 IP 或加 `--ip`），数说不清的习惯（禁用色、主角怎么选）在它的规矩文件「封面」一节：做之前先读 `python3 "$AI/bin/cutdesk_config.py" rules --project <项目根>`（在 `配置档/<IP>/规矩.md`）。**照做，不要自行换画风、字体、颜色或版式**；用户提出新要求时先改本能力或那个 IP 的配置档（见项目根目录 AGENTS.md），再按新规则做。下文说的“蓝”“深蓝”“红橙”“米白”指 IP 的主角色、标题色、圈箭头色、副标题字色。

## 定稿规范

- **画风**：细而均匀的深灰线稿，米白底，只给本期主角涂一个颜色（IP 的主角色，配置档 `封面.主角色相`；最多再点缀一件小物件）。底图由 AI 生成，AI 仍按陶土色画（脚本靠它识别主角），排版时脚本自动换成主角色，提示词模板写在 `scripts/thinkcut_cover.py`，画风只靠提示词文字描述；**生图一律按文字重新生成，不让 Codex 打开或修改任何图（含画风参考图和竖版底图）**——2026-10-24 用户：用图改图越改越模糊。每张生图任务单开头脚本自动带一句“不打开、不参考任何旧图，按文字新生成”；任务单以外另提生图要求（如多出几个方向让用户挑、重出一版）时也照这句办，不拿旧图去改（2026-11-21《261118 装修最后那点细节》用户再次强调：每次都让 Codex 按文字新生成，不能用图改图）。`assets/style_ref.png` 只留作人看的参考。
- **主标题**（两行为主，三行也可以，2026-11-20 用户定；项目.json 里只有一行时按逗号自动拆成两行，逗号不上封面，2026-11-12）：字体是配置档 `封面.标题字体`（宋体），第一行常规、其余行细体；颜色是 `封面.标题色`；字距收紧，行距 1.3 倍，字形横向压窄到 `封面.标题横向压缩`。文字墨迹离左边、离上边都是短边的 7.5%，3:4 时是 81px，两边距离必须相等。
  - **三行**（如 `为什么外地／灯光设计／我不接了`）：`init` 时再加 `--line3`（`--line2` 也要给；一行里有两个逗号也只拆两行，不会自动变三行）。所有版式、两种画风、三种比例都能排。字号是两行的 9 成（3:4 时 104px），行距、压窄、边距规则不变；下面的副标题色块、插图、格子、照片自动往下让。`--circle` 可以圈任意一行；圈不在最后一行时，指向格子的箭头从这一行和下一行的空隙里横着穿出去再拐向格子。
  - 三行会让插图、照片、格子变小一点。挤得比较明显的：线稿三步流程（3:4 小图变小）、实拍数字大字 3:4（字缩到约 84px，必要时照片上边往下让）、实拍拍立得 3:4（四张整体缩小约 1 成）、单主角 16:9（字不再放大到 1.45 倍）。文字本身就长、插图要大的期，优先用两行。
- **副标题**：标题色色块配副标题字色的**黑体**（`封面.副标题字体`，冬青黑体 W6，3:4 时 76px、白描边加粗、四周只留很窄的边、字填满色块（2026-10-31 用户：白字和蓝底面积差不多），不压窄），手机上不放大也看得清（2026-10-24 用户：细仿宋看不清、发虚）。色块右边和画面右边的距离也是同一个边距，色块放在标题和插图之间的空白里（大约从标题往下 3 成处，靠右），一条红橙手画箭头（见下条）从色块朝主角那一侧水平出发，向外甩一道大弧再回钩指进主角顶部；主角在色块正下方时从底边出、往右鼓再钩回（2026-10-24 用户画过样子）。16:9 标题和副标题放大到 1.45 倍、往画面中间伸（封面图小，字太靠边看不见）；放大后插图要下移太多时自动收小一点，下移不会把主角推出画面。位置由脚本根据主角自动算。
- **不给副标题**（2026-11-21 用户：“封面文字里不分主副标题，只要把封面文字写在封面里就可以了”）：`init` 不加 `--sub`。所有版式、两种画风、三种比例都能出：不画色块，红圈圈住标题关键词，红箭头从圈指向主角（四宫格等本来就从圈出发的照旧），保持红线风格。
  - 关键词用 `--circle` 指定；不指定时**默认圈最后一行，最后一行中间有标点时圈到第一个标点为止**（如“灯装哪？才够亮？”圈“灯装哪？”），登记时会打印出来。数字大字不圈（它有红下划线）；局部放大不给副标题时也圈。
  - 箭头默认指主角顶部。要指主角里的某个小部件，加 `--arrow-at "左右,上下"`（各 0–1，按主角上色部分的外框算；实拍按留色区），如灯在光束末端时 `--arrow-at 0.5,0.64`；这时箭头先绕到主角外面空的那一侧再钩进去，不穿过主角。只给单主角（和实拍竖图满版）用。
- **圈和箭头**（2026-11-12 水电那期定稿，用户："以后这个线箭头颜色可以按照你这个来，包括画的方法也按这个来"）：颜色是 `封面.圈箭头色`，线宽 7px（短边 1080 时），手画感——
  - 圈：`--circle 关键词` 圈住主标题里的关键词。圆角椭圆，左边正好落在关键词和前一个字的空隙中间、不碰前一个字；右边略抖略胀，笔画多绕一小段、两头在右边交叠，像一笔画成。关键词以全角问号等窄标点结尾时，圈也把标点整个圈进去（2026-11-21 修了量法）。
  - 箭头：弯线，线身带一点手抖、越靠近箭头越稳；箭头是两条一样长的短线，沿线尾切线左右对称各 30°，不用实心三角。单主角时从副标题色块指向主角（不给副标题时从圈出发）；四宫格时从圈的右下方出发指向格子。
  - 红线压到关键词以外的字，脚本会报警。
- **多主角／四宫格**（2026-11-12 水电那期，用户："这4件事儿正好可以做个四宫格的图，每宫格里画这个内容""四宫格图尽量紧密一些"）：一期讲四样东西时用。副标题色块在左上，下面两行标题，红圈圈住关键词，弯箭头指向格子；格子紧凑，圆角外框加细分隔线，每格左上两行黑体标签（自动加 ①②③④），下面放这一格的小图（只给这一样东西上蓝色）。一律 2×2；3:4 文字在上、格子在下，横版由脚本在“文字在上/在左 × 标签在格子上方/左边”里挑小图最大的排法。四张小图画在同一张横版底图里，三种比例共用，只生 1 次图。
- **左右对比**（`--layout compare`；2026-11-14 用户在 Design 画板上确认四种都要）：讲“错的做法 vs 对的做法”时用。文字区和四宫格一样（色块左上、两行标题、红圈圈关键词），弯箭头指向右边那格；下面圆角外框分左右两格，每格左上两行黑体标签（不加 ①②）。左格是错的：小图去色成浅灰、压一个红橙手画叉；右格是对的：主角上蓝。横版也保持左右两格、文字在上。两张小图画在同一张横版底图里，只生 1 次图。
- **数字大字**（`--layout number`；2026-11-14 同上）：卖点是一个数（价格、尺寸、年数）时用。色块左上 → 两行标题 → 特大宋体深蓝数字（字号约主标题 3.5 倍，太宽自动缩到不超右边距）＋细体单位（约主标题 1.2 倍，和数字底线对齐）→ 数字下面一道红橙手画下划线 → 插图缩小放在数字下面，中间至少留一个主标题字高。不画色块指向主角的箭头，不圈关键词。底图和单主角共用（只要一张竖版底图，横版复用同一张画）；横版由脚本在“插图在数字下面／在文字右边”里挑插图大的。
- **三步流程**（`--layout steps`；2026-11-14 同上）：讲“三步搞定”时用。文字区同四宫格，关键词可圈可不圈，不画指向格子的大箭头（格子里已有小箭头，再加会乱）。下面圆角外框分三行，每行左边两行黑体标签（自动加 ①②③）、右边小图（主角上蓝），行与行之间在标签那一栏压一个朝下的红橙手画小箭头。横版由脚本在“三行／三列（列间小箭头朝右）× 文字在上／在左”里挑小图最大的排法。三张小图画在同一张横版底图里，只生 1 次图。
- **局部放大**（`--layout zoom`；2026-11-14 同上）：主角是藏在大场景里的一个小部件时用。两行标题在左上，色块在标题下方靠右，弯箭头从色块指进放大圆；左下是整体场景小图（去色，只剩灰线），上面在 `--zoom-at` 指定的位置画一个深蓝小圆环；右边一个深蓝描边的大圆里放局部特写（主角上蓝，圆形裁切），小圆环和大圆之间连一条深蓝细线。横版是标题、色块、整体小图一栏在左，大圆在右。有副标题时不圈关键词；不给副标题时圈关键词，箭头从圈指进大圆。两张小图画在同一张横版底图里，只生 1 次图。
- **尺寸**：3:4 是 1080×1440；4:3 是 1440×1080；16:9 是 1920×1080。单主角、数字大字只生一张竖版底图（1024×1536）：3:4 直接用；**4:3 和 16:9 默认复用这张用户确认过的画**——脚本把整幅画抠出来，放在标题下面或标题右边（挑画放得大的），场景画到图边的那几侧渐渐淡成纸色（2026-11-21 用户：横版另生成了另一张图，“封面3:4那个是OK的，其他的都是有错的”）。四宫格等本来就共用一张横版底图的版式不变。
- **脚本会自动处理这几件事**：
  1. 标题和插图之间至少留一个字高。不够时，脚本把插图整体往下移，上面补同样的米白纸面。
  2. 副标题色块和标题在同一高度时，两者至少隔开约 300px。
  3. 箭头从色块侧边出发、大弧回钩指进主角顶部；弧线伸出画面会报警。
  4. 排版后查整幅画和主角有没有被画面边缘裁掉（只看画四周本来留着纸边的那几侧，满幅的场景画到图边不算）：被裁就把整幅画缩小、上提到标题下面，最多缩到 6 成，还放不下才报警（2026-11-21，竖版底图排 3:4 要裁上下、画贴底时就会被裁）。
  5. 换色后查还有多少粉橙色（光被画成渐变或光晕时，换色换不干净），超过 0.5% 就报警；红橙圈和箭头不算在内（查的是底图）。合格样例都在 0.07% 以下。
  6. 主角是几个差不多大的同类小东西（如一排筒灯）时，按它们的合计面积认主角（单个不到画面 0.4% 也认），箭头只指最靠边的一个：箭头从标题红圈出发时指靠红圈的那一头，从副标题色块出发时指靠右上的那一头，不横穿另外几个。横版复用竖版画、画被缩小时，认主角的面积门槛按缩小比例一起降低（2026-11-21《261118 装修最后那点细节》：4 个筒灯各约 0.16%、3 个大筒灯各约 0.31%，都报“没找到陶土色主角”、没画箭头；16:9 箭头横穿另外两个筒灯）。
  7. 查底图四边有没有被 AI 画上整圈外框（每条边往里 8% 以内有一条几乎连到头的线，三条边以上都有就算）：`gen` 出图后马上查，`render` 时再查一次，查到就报警“底图被画了一圈外框”，照样出图、不拦。线稿提示词已写明不要外框、四周留纸边（2026-11-21《261118 装修最后那点细节》：B 梯子、挑空筒灯两张底图都被画了整圈外框，3:4 下边被裁）。
- **不要**加左上角标签、人物、品牌字，也不要毛玻璃；IP 规矩里写了禁用色的也不要。
- **部件画在真实安装位置**（2026-10-24 用户：通气阀在浴室柜里，不能为了留空位挪到柜外）。scene 里写清它装在哪。

## 流程（Claude 和 Codex 都按这个做）

程序目录：`AI=$(cd -P ~/.claude/skills/thinkcut-cover/../../.. && pwd)`（技能链接指着的使用版）。脚本：`S="$AI/封面/skill/thinkcut-cover/scripts/thinkcut_cover.py"`。所有命令都用 `python3 "$S" …`；从 shell 启动的命令一律加 `< /dev/null`。

**给用户看图**（底图、成图、总览都一样）：在 Claude App 里发图片卡片之前，先把 DIR 所在的项目文件夹加进会话，卡片才点得开；用户仍说点不开，就运行 `open -a Preview "<图片完整路径>"`，在“预览”里直接弹出来（2026-11-21《261118 装修最后那点细节》用户：“你每次给我的这个都点不了”）。

**不等用户选，先出齐**（2026-11-22 用户定“先做出来再改”：“按照AI的想法直接做就行了，不用来问我，等做完了我边看边改”；取代原来的“用户选了方向才出横版”）：3 个方向的 3:4 出好后，**AI 自己挑一个最合适的方向，直接在那个子文件夹里出 4:3、16:9 并 `cover-register` 登记**，再把 3 个方向一起发到审片台（下面那条命令加 `--draft --assume "我先按 B 出齐了三种比例，因为……；想换方向点另一个‘选这个’"`）。用户点了别的方向：在那个方向里补出 4:3、16:9、重新登记。用户写了要求：照改。底图不合格（下面“验底图”）、生图失败：自己判断重出一次，不用先问；同一个方向连续两次都不合格才停下告诉用户（额度是用户的）。开始前不用再跟用户说要用几次生图，做完在卡片的 `--assume` 里写明用了几次。

**3:4 一次出 3 个方向，发到审片台**（2026-11-22 用户定）：同一套封面文字，出 3 个不同方向（不同画风，或同一画风不同主角、不同场景；四宫格等版式也可以当一个方向）。每个方向一个子文件夹 `DIR/底图方向/A_<几个字>`、`B_…`、`C_…`（下文的 DIR 换成这个子文件夹），各自按下面第 3–6 步 init → gen → 验底图 → `render --ratios 3:4`；一个方向用 1 次生图，开始前跟用户说这期要用 3 次。3 张 3:4 都出好后，发到这条片子的审片台“封面”栏（片子目录是 `<项目根>/02_制作/自动剪辑`）：
   `python3 "$AI/口播自动剪辑/skill/thinkcut-edit/scripts/thinkcut_edit.py" workbench <片子目录> --publish 封面 --kind 多选一 --key 封面方向 --title "封面 3:4 三个方向" --look "三个方向：…。看主角一眼认不认得出、标题压没压画、箭头指得对不对，选一个" --files <A 的 3:4 图>,<B 的 3:4 图>,<C 的 3:4 图> --labels "A …,B …,C …" < /dev/null`（路径之间用英文逗号）
   用户在审片台点“选这个”就是定了（`workbench <片子目录> --list` 读到选的哪个；用户写了要求就在那个方向里改，改完 `workbench <片子目录> --reply 编号 --files 新图 --labels … --note "改了什么"` 换新版）。之后只在选中的那个子文件夹里出 4:3、16:9（第 7 步）并登记。还没有片子目录（没走 thinkcut-edit）时，才把 3 张图照上一条发给用户选。

1. **收集文案**：项目先取项目文案里的“封面文字”：`python3 "$AI/视频项目管理/bin/project.py" script <项目根> --part 封面`（文案里没有「## 封面文字」小标题会报出来：不问用户，AI 按口播内容定一版封面文字（用什么方法定看 IP 规矩），写进项目文案的「## 封面文字」一节（视频项目管理 `script_doc.set_section`；审片台口播剪辑栏左下角“标题 · 封面文字 · 原稿”改的也是这一节），并在审片台卡片的 `--assume` 里写明“封面文字是我拟的”，2026-11-22）。需要主标题（一般两行，文案写了三行就照三行）、副标题（文案没写就不要，不替用户拆一行出来当副标题），以及本期讲什么（哪个空间、主角是什么）。**文案里有封面文字就直接用，不用 dbs 标题技能重新定、不出候选让用户重选**（2026-11-21 用户：“写封面、写标题的时候，咱们在MD文档里都有了，让他去那里找去”）。文案里有的逐字用、**不改用户写的字**；缺的那一项 AI 先拟一版并写明是拟的（2026-11-22 起不停下来问）；用户要候选时可以给 3 组让他选。保存位置（下文记作 DIR）：项目一律用 `<项目根>/02_制作/封面制作/`；不在项目里的才用 `~/Desktop/封面_<YYYYMMDD>_<第一行>/`。只有文案里没有封面文字、用户又要 AI 出时，才先用 dbs 的标题技能定选题和封面文字。
2. **写画面描述**：把主题写成英文 `scene`（空间、主角在哪、台面或周围只放少量物件）和 `subject`（要上色的那一样东西）。主角要有明确的顶部，方便箭头指。例子：
   - 烟道：scene = `the kitchen of a freshly renovated older Chinese apartment; in the corner beside the range hood stands the vertical exhaust flue shaft, neatly boxed in flush with the wall; a clean countertop below, only a few objects`，subject = `the boxed-in flue panel`
   - 卫生间防水：scene = `a small renovated bathroom of a Chinese apartment, shower corner with a low curb, tiled walls`，subject = `the waterproofing layer rising 30cm up the shower walls`
   - **主角怎么选**看 IP 规矩「封面」一节。
3. **登记**：`python3 "$S" init DIR --line1 … --line2 … [--line3 …] [--sub …] [--circle 关键词] [--arrow-at 0.5,0.64] --scene "…" --subject "…"`（只给 `--line1` 且带逗号时自动拆两行；主标题三行时加 `--line3`；没有副标题就不写 `--sub`；下面各版式的登记同样适用）。
   - **四宫格**（一期讲四样）：`python3 "$S" init DIR --layout grid --line1 … --line2 … --sub … --circle 关键词`，再按左上、右上、左下、右下顺序各给一组 `--cell "标签第一行|第二行" --cell-scene "<英文：这一格画什么，特写、几乎不带背景>" --cell-subject "<英文：这一格上色的部分>"`。然后跳到下面“四宫格流程”。
   - **左右对比／三步流程／局部放大／数字大字**：见下面“新版式流程”。
4. **竖版底图**（消耗 1 次生图）：
   - Claude：`python3 "$S" gen DIR portrait < /dev/null`。这一步由 Codex 出图，约 1–3 分钟，放后台运行，等它结束。
   - Codex：`python3 "$S" gen DIR portrait --task-only`，然后打开打印出的任务文件，用自带的生图工具照做，存到任务里写的路径。
5. **验底图**：打开 `DIR/_制作文件/bg_portrait.png` 看六点：上方 45% 基本是空白；只有主角（最多再加一件小物件）是陶土色（排版时会换成蓝色）；颜色是平涂、边线清楚，光没有画成渐变或光晕；画面里没有文字；画风是线稿，不是照片；四周没有整圈外框（脚本出图后也会自动查，见上面“脚本会自动处理”第 7 条）。不合格就自己重出一次（会再用 1 次额度；2026-11-22 起不先问），第二次还不合格再告诉用户原因。
6. **出 3:4**：`python3 "$S" render DIR --ratios 3:4`。看输出的"警告"和成图：标题有没有压到画面、箭头是否指向主角。三个方向都出好后按上面“不等用户选，先出齐”：AI 先挑一个出横版，再一起发到审片台。
7. **出横版**（不用再生图；AI 挑的那个方向直接出，不等用户确认，2026-11-22）：直接 `render DIR --ratios 4:3,16:9`，横版复用竖版那张画。只有用户明确要另画一张横版时才 `gen DIR landscape`（再用 1 次生图）；这时 render 会提醒“横版和竖版不是同一张画”，要先把横版给用户看。脚本会自动生成 `DIR/总览.jpg`。逐张看过后，把成品文件发给用户，或给出可以点开的完整路径。做完用 thinkcut-project 的 `cover-register` 登记到 `03_成片/封面/`，并在 Finder 里直接选中成品交给用户。
8. **只改字**（底图不变）：用新文字重新运行 `init`，scene 和 subject 保持不变，再 `render`。不用重新生图。

## 四宫格流程

1. 登记见上面第 3 步。每格标签短一点（一行约 5 个字以内），写这一格讲的事；scene 写真实安装位置。
2. **底图**（消耗 1 次生图，三种比例共用）：Claude `python3 "$S" gen DIR grid < /dev/null`；Codex 用 `--task-only` 后自己出图。
3. **验底图** `DIR/_制作文件/bg_grid.png`：四张小图各在四分之一里、中间有空隙；每张只有要上色的部分是陶土色；没有文字和边框。
4. `python3 "$S" render DIR --ratios 3:4,4:3,16:9`（不用再生图；2026-11-22 起不等用户确认 3:4，一次出齐，发到审片台事后看）。之后登记同单主角第 7 步。
5. 四宫格的警告：“四张小图之间没留空”“第 N 格没找到陶土色部分”→ 重出底图；“红圈或箭头压到了关键词以外的字”“第 N 格标签太长”“第 N 格小图压到了标签”→ 改短关键词或标签再 render；“排不下”→ 主标题或副标题改短。

## 新版式流程（左右对比、数字大字、三步流程、局部放大）

2026-11-14 用户在 Design 画板上确认四种都要。收集文案、写画面描述同上面第 1、2 步。

1. **登记**（标签两行用 `|` 隔开，一行约 6 个字以内；scene 写特写、几乎不带背景）：
   - 左右对比：`python3 "$S" init DIR --layout compare --line1 … --line2 … --sub … --circle 关键词`，再给两组 `--cell "标签|第二行" --cell-scene "<英文>" --cell-subject "<英文：上色的部分>"`，顺序固定**先错的、后对的**。
   - 三步流程：`python3 "$S" init DIR --layout steps --line1 … --line2 … --sub … [--circle 关键词]`，再按第一、二、三步给三组 `--cell … --cell-scene … --cell-subject …`。
   - 局部放大：`python3 "$S" init DIR --layout zoom --line1 … --line2 … --sub … [--zoom-at "0.5,0.5"]`，再给两组 cell，顺序固定**先整体场景、后局部特写**（标签不上封面，只当说明，仍要给）。`--zoom-at` 是小圆环在整体小图里的位置（左右,上下，各 0–1，默认正中）；先按默认出一版，看图后再调。
   - 数字大字：`python3 "$S" init DIR --layout number --line1 … --line2 … --sub … --number 400 [--unit 块钱] --scene "…" --subject "…"`。
2. **底图**：
   - 左右对比、三步流程、局部放大：消耗 1 次生图，三种比例共用。Claude `python3 "$S" gen DIR compare|steps|zoom < /dev/null`；Codex 用 `--task-only` 后自己出图。
   - 数字大字：和单主角一样，`gen DIR portrait` 一次，横版复用同一张画（共 1 次）。
3. **验底图**：`bg_compare.png` 左右各一张、`bg_steps.png` 并排三张、`bg_zoom.png` 左边整体右边特写；小图之间有空隙，要上色的部分是陶土色，没有文字、边框、箭头、叉或圆圈。左右对比两张要同一视角同样大小；局部放大的特写要大致方正、居中（要放进圆里）。数字大字的底图按单主角第 5 步验。
4. `python3 "$S" render DIR --ratios 3:4,4:3,16:9`（2026-11-22 起不等用户确认 3:4，一次出齐，发到审片台事后看）。之后登记同单主角第 7 步。
5. 新版式的警告：“N 张小图之间没留空”“第 N 张没找到陶土色部分”→ 重出底图；“第 N 格标签太长”“第 N 格小图压到了标签”“小箭头压到了标签”“红圈或箭头压到了关键词以外的字”→ 改短标签或关键词再 render；“数字太长”→ 告诉用户改短数字或单位；“特写小图被圆裁掉了…”→ 看成图，主角被切就重出底图；“小圆环被放大圆盖住了”→ 换 `--zoom-at`；“排不下”→ 主标题、副标题（或数字）改短。

## 实拍留色画风（`--style photo`）

2026-11-20 起。用户在《261114 千万的房子》上试出、确认固化（当时的规格书和 14 版成图在那期 `02_制作/封面制作/实拍拼贴/`）。默认仍是线稿；用户要“实拍/照片/现场感”的封面，或点名“实拍留色”时才用。

- **画风**：底图是 Codex 按文字生成的**黑白照片，只有问题部位保留彩色**（隐患、偷工减料的那一处）。排版完全沿用上面的规范：IP 的标题字体和标题色、副标题色块、圈箭头色的手画圈和箭头、标题关键词红圈。**照片不调色**（不换蓝、不去色），只等比缩放加裁切，绝不拉伸。留色区域由脚本按饱和度自动找，红圈圈住它，箭头尖落在彩色像素上。
- **版式**（`init … --style photo --layout …`；标签两行用 `|` 隔开）：

| 版式 | 登记 | 底图（`gen DIR …`） |
|---|---|---|
| 单主角（默认） | `--scene "…" --subject "…" [--circle 关键词]` | `photo`：一张横版照片，三种比例共用（1 次） |
| 数字大字 | `--layout number --number 10 --unit 个隐患 --scene … --subject …`（不圈） | `photo`（1 次） |
| 局部放大 | `--layout zoom --scene … --subject … [--circle …]`（特写从同一张照片的留色区裁，不用 `--zoom-at`） | `photo`（1 次） |
| 四宫格 | `--layout grid --circle …` + 4 组 `--cell/--cell-scene/--cell-subject`（左上、右上、左下、右下） | `grid`：一张 2×2 拼图（1 次） |
| 左右对比 | `--layout compare` + 2 组 cell：**先表面看着没问题的（`--cell-subject none`，全黑白）、后露出问题的** | `compare`：左右两张拼图（1 次） |
| 竖图满版（只有实拍） | `--layout full --scene … --subject … [--circle …]` | 3:4 用 `portrait`，确认后横版用 `landscape`（共 2 次） |
| 三联竖条（只有实拍） | `--layout triptych --circle …` + 3 组 cell（左、中、右；标签一行） | `triptych`：三张竖照片拼图（1 次） |
| 拍立得拼贴（只有实拍） | `--layout polaroid` + 4 组 cell（第 1 张是主角，放最上面、画圈和箭头；标签不上封面，只当说明，仍要给） | `polaroid`：2×2 拼图（1 次） |
| 六宫格（只有实拍） | `--layout six --circle …` + 6 组 cell（从左到右、从上到下） | `six`：3×2 拼图（1 次） |

  三步流程暂不支持实拍留色（会拦住并提示）。`--scene` / `--cell-scene` 写英文，写清在哪、问题部位多大、放哪（如 `a bedroom headboard feature wall …; one veneer panel pried open exposing cheap particle board, about a quarter of the frame, right of centre`）；`--subject` / `--cell-subject` 写要留色的问题部位；单张照片的版式可加 `--grey "veneer, bed and walls"` 点名容易被误上色、要保持灰的东西。**提示词里不要写任何要印在物体上的字**（如“外皮印 CAT 5E”），会生出真字。
- **流程**：`init` → `gen DIR <底图> < /dev/null`（Codex 用 `--task-only` 后自己出图）→ 验底图（下条）→ `render DIR --ratios 3:4` → 接着 `render DIR --ratios 4:3,16:9`（只有竖图满版要先 `gen DIR landscape`；2026-11-22 起不等用户确认，出齐后发到审片台）。生图偶尔要十几分钟（那期三联一张约 17 分钟），先看日志末尾，不要当失败重开。
- **验底图三条**（打开 `_制作文件/bg_photo*.png` 人工看，不合格告诉用户原因、问是否重出）：
  1. **照片质感**：像手机拍的真实现场照片，不是插画、3D 渲染或线稿。
  2. **只有问题部位有颜色**：其余全是中性灰；问题部位够大、不贴着照片边。拼图要每张都这样，张与张之间有白缝。竖图满版的竖版照片上方约 40% 要是安静的空墙（标题压在那里）。
  3. **无人无字**：没有人、脸、手（玻璃反光里的人影也看一眼）；没有文字、标志、水印。设备外壳上极小的仿真铭牌字样，缩到封面上看不出的可以接受。
  脚本能判断的会直接报警：“没找到留色区域”（几乎没颜色或彩色块太小）、“彩色面积占 N%，不像只有问题部位留色”、“照片整体不是黑白”→ 重出底图；“底图里没找到 N 张照片之间的白缝”→ 看成图有没有切歪，切歪就重出。
- **render 的其它警告**：“红圈或箭头压到了关键词以外的字”“红线压到了小标签”“箭头或红圈伸出画面边缘”“留色区域贴着照片边，红圈圈不住它”“留色区域伸到了标题纸块下面”（竖图满版）→ 看成图，必要时改短文字或重出底图；“第 N 格/条标签太长”→ 改短，横版六宫格、三联建议标签写成两行（`电视墙|不承重`）；“主标题太长”“数字太长”同线稿。
- **已知问题**：三联、六宫格的小标签在缩略图里偏小；横版 4:3 的六宫格标签一行超过约 5 个字就挤在一起（写成两行就好）；左右对比 16:9 照片偏小、左边留白多；拍立得 4:3 照片偏小。

## 额度与失败

- 每期 3:4 出 3 个方向，每个方向正常只用 1 次生图，一期共 3 次（2026-11-22 起；单主角、数字大字的横版复用竖版画；用户明确要另画横版时才多 1 次；实拍竖图满版仍是竖版、横版各 1 次）。Codex 拒绝或出图失败也算额度，失败后自己重试一次（2026-11-22 起初稿阶段不先问）；同一张连着两次失败就停下告诉用户，**不要一直重试**。每次生图都记在 `DIR/_制作文件/gen_count.log`。
- `render` 出现以下警告时：
  - "没找到陶土色主角"：先看底图——**主角上了色、只是东西本来就小**（墙上的开关面板、插座、龙头；上色不到画面 0.4%）：不重出，在 `_制作文件/spec.json` 加一行 `"small_subject": true`（或 `init` 时就加 `--small-subject`）再 `render`，箭头照画，不花生图额度（2026-11-23 初稿模式实测：开关面板只占 0.20%、插座 0.32%，两个方向都没画箭头）。主角是这类小物件时 `init` 就加上。底图真没给主角上色：重出底图一次。
  - **初稿阶段还是没箭头怎么办**（2026-11-23）：按上一条处理（小物件开开关；真没上色自动重出一次）后仍报这条警告，不再重出、不问用户：照出这一张，换一个有箭头的方向出齐三种比例；发到审片台时在 `--assume` 里写明“哪一张没画箭头、原因是什么”。
  - "找不到放副标题色块的空位"：主角上方太挤。可以换个 scene 描述重出，或告诉用户由他决定。
  - "标题下方留白不够"：上方留白太少，要重出底图。
  - "箭头弧线伸出画面边缘"：看成图，箭头被裁就换构图重出底图。
  - "主标题太长，缩到最小字号仍超出右边距"（三行时任何一行太长都会报）／"副标题太长，缩到最小字号色块仍超出左右边距"（2026-11-13）：字已经缩到下限还顶到画面边，告诉用户把这一行改短（不替用户改文案），改完重新 `init` 再 `render`。
  - "主角被画面边缘裁掉"／"…被画面边缘裁掉，缩到 60% 仍放不下"：脚本已自动缩小上提过还不行，多是画占满了整张图，重出底图时 scene 里写明画要紧凑、四周留纸边。
  - "横版和竖版不是同一张画"：用的是另生的 `bg_landscape.png`，先把横版给用户看；用户要和竖版一致，就把这张移进回收站再 render，横版会复用竖版画。
  - "底图被画了一圈外框"：AI 给整张底图加了边框，排版时会被裁、边上露出硬线。先把底图给用户看，问是否重出（会再用 1 次额度）；用户不重出就如实说明成图带框。
  - "底图换色后还残留 N% 的粉橙色"：光或主角画成了渐变、光晕，成图边缘会发粉橙，告诉用户、问是否重出底图（提示词已要求平涂）。
- 出现警告时不能当作完成交付，要如实告诉用户。
