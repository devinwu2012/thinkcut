# 上传到蚁小二（thinkcut-upload）

2026-10-24 从 thinkcut-project 拆回成单独技能。下面是通用流程，照做；**这个 IP 的发布默认（平台、各平台封面和开关、分类、原创、标题方向）先读它的规矩**：`python3 "$AI/bin/cutdesk_config.py" rules --project DIR` 的「发布」一节（在 `配置档/<IP>/规矩.md`），能写成数的在配置档 `发布.*`、程序自己读。

- 程序目录：`AI=$(cd -P ~/.claude/skills/thinkcut-upload/../../.. && pwd)`（技能链接指着的使用版；在开发版试验时换成开发版目录）。
- 工具：`python3 "$AI/视频项目管理/bin/project.py" <命令> DIR`，DIR 是项目根目录（在这个 IP 的片子文件夹里：`python3 "$AI/bin/cutdesk_config.py" show --key 片子文件夹`）。
- 只存**蚁小二内部草稿**，绝不调用 `yxer publish`。所有调用走 `yxer-safe`（Key 在本机钥匙串；它会拒绝一切发布命令）。新 Mac 先运行 `bash "$AI/视频项目管理/bin/setup_mac.sh"` 和 `yxer-safe key set`。
- 平台字段以 CLI 自带文档为准：`"$(npm root -g)/@yixiaoermail/cli/references/"`（`platforms/video/<平台>.md`、`topic-tags.md`、`save-draft.md`）。

## 流程

- **缺平台先提示**（2026-11-12）：`accounts` 和 `upload` 预检对照这个 IP 配置的平台（配置档 `发布.平台`），缺哪个、为什么（没绑定、账号失效、项目里没启用）都列出来，回执里也记一份；照实告诉用户，不默默少发。
- **说“完成／已生效／会自动……”之前要有依据**（2026-11-12《水电》：把旧文件当新渲染报“已出完”、说“会自动截取标签”其实不会、把封面位置说错）：汇报里附上这次的依据——当次命令输出、文件修改时间或路径；没核实的明说“还没核实”，不说“会自动”除非程序里真有这一步。
- **超平台上限先拦**（2026-11-12）：`upload` 预检按各平台实时结构查标题、简介字数和话题个数，超了一次列全、一个文件都不传（《水电》2.7GB 传完才被拦两次）。按提示改项目.json，个别平台超的用 platform_extra 单独写。

0. **成片得是用户确认后导出的（程序会拦）**（2026-11-22 用户定“先做出来再改”：前面都按 AI 的判断先做成初稿、不问，只在整片导出和上传前留闸；2026-11-01 用户：“必须我在时间线内看完之后……再导出这个 4K 的视频上传”）：用户在审片台“审核线”栏点过“这一栏定了”，thinkcut-edit 的 `export` 才导整片，并记在片子目录 `job.json` 的 `export_ok`。`upload`（预检也算）发现走了剪辑的片子没有这条记录就停——请用户去审片台点，AI 不能替用户点，对话里转述的话也不算。正式发布照旧只能用户自己在蚁小二客户端点。
1. **登记定稿并填资料**：先 `register-final DIR --video 03_成片/<成片>.mp4 --srt 03_成片/字幕/<同名>.srt --project <达芬奇工程名> --timeline <最终时间线>`；再填 `项目.json`：
   - **标题、简介、标签先从项目文案 `03_成片/<项目名>.md` 取**（2026-11-22 起在 03_成片，老项目没搬时程序会读 02_制作 那份）（2026-11-21 用户：“写封面、写标题的时候，咱们在MD文档里都有了，让他去那里找去”）。文案里有的直接用，**不再出备选、不建文档让用户重选**：
     1. `script DIR` 看文案里有哪几类（标题、封面文字、口播正文、简介、标签、小红书标题）；`copy-draft DIR` 生成 `02_制作/发布文案素材.json`（口播原话、口播里的数字、封面文字、文案里已有的标题／简介／标签／小红书标题、写法要求）。封面文字项目.json 和文案两边不一样时两份都列出，问用户以哪份为准。
     2. **文案里有标题**：直接用。**文案里没有标题**（老项目）：才按老办法出备选——出哪几个方向按这个 IP 规矩的「品牌和口吻」，每个备选注明筛的是谁；**AI 自己先选一个最合适的直接写进去**（2026-11-22 用户定“先做出来再改”，取代原来的“建 Claude 文档给用户选、确认后才能写”），其余备选发到审片台“上传文案”栏的卡片上（`workbench --publish 上传文案 --kind 改字 --draft --assume "标题文案里没有，我选了这一个，另外几个是……"`），用户要换直接说。不要把“用户确认了”记下来——没确认过。
     3. **简介、标签文案里有就直接用；没有**（2026-11-21 用户选“AI 写一版你过目”）：AI 写一版（**只一版，不出多个备选**）**直接 `copy-apply` 写进去，不等用户过目**（2026-11-22 用户定“先做出来再改”，取代 2026-11-21 的“AI 写一版你过目、说行才写”）：它出现在审片台“上传文案”栏的文本框里，用户直接改；同时发一张 `--kind 改字 --draft` 的卡片说明“简介、标签是我写的初稿”。写法：**简介写给平台搜索**（用户：“简介是没人看的，但是它会给搜索来看”）：问题词＋方案词＋产品词串成通顺的句子，数字和价格只用口播原话；**标签 8–10 个**（抖音、B 站话题最多 10 个），不带 #，按重要度排；顺带写 B 站分类。
     4. **小红书标题**（最多 20 字）：文案里有「## 小红书标题」就用；没有且标题超过 20 字时，AI 按原标题缩一版 20 字以内的，和简介标签一起直接写进去、在审片台卡片上说明（2026-11-22 起不等过目）。
     5. 写好后（不用等用户说行），把这一版写成 JSON（title、description、tags，可带 bilibili_category、`platform_titles: {"小红书": "…"}`），`copy-apply DIR --file 定稿.json` 写进项目.json，**同时把文案里还没有的简介、标签、小红书标题补进项目文案**（「## 简介」「## 标签」「## 小红书标题」，放在「## 口播正文」前面；已有的不动），下次直接从文案取。copy-apply 会拦：标题／简介／标签／小红书标题和文案里写定的不一样（要改先改文案）、空标题、标签个数不对或带 #、简介（含各平台单独的简介）里口播没说过的数字、写错的平台名、发小红书却没有 20 字以内的标题。
     6. 某个平台的简介要和通用简介不同时（如小红书写长一点），定稿 JSON 里加 `platform_descriptions: {"小红书": "…"}`（平台名只能是 抖音、快手、小红书、视频号、哔哩哔哩、Youtube），写进 `platform_extra.<平台>.description`，上传时该平台优先用它、没写的平台用通用简介，话题照旧拼在后面。项目.json 里没有 `platform_copy` 这个字段，别用；发现了，`copy-apply` 和 `upload` 会提醒“程序不认”。
   - `materials_confirmed: true`（成片是用户在审片台定了以后导出的、封面是用户在审片台“封面”栏点过“选这个／可以／这一栏定了”的那一版，才改成 true；初稿阶段保持 false，所以初稿不会被传上去）；`original`、`youtube_category` 建项目时按 IP 配置填好；`bilibili_category` 用 `yxer-safe query categories <B站账号ID> --paths --json` 查到的完整名称，默认分区看 IP 规矩。
   - `targets`：没有时先跑 `accounts DIR` 生成（封面和横版按默认填好：B 站 16:9、其余 3:4，抖音、视频号加横版 4:3；能用的账号**全部启用**，IP 配置 `发布.只发这些平台` 为 true 时只启用清单里的平台）。已有 targets、后来才修好某个平台的账号：`accounts DIR --fill-missing`，只给项目里一条都没有的平台补上，已有平台（含用户关掉的）一个字不动，并说明补了哪几个；不带这个参数仍然不覆盖。全部分发是不是这个 IP 的规矩看它的规矩文件；用户这次明说不发哪个平台才关掉那个。
1.5 **查平台活动和话题（可选，2026-11-01）**：`activities DIR` 只读查询各平台正在办、和本片相关的活动（过期的、无关的去掉）和话题播放量（目前只有抖音能搜话题），写 `02_制作/平台活动候选.json` 并打印摘要；视频号、YouTube 常查不到。用户挑中的：活动话题或额外话题写进 `项目.json` 的 `platform_topics`（如 `{"小红书": ["我在小红书搞装修"]}`，只加到那个平台）；抖音挑战、视频号活动要挂对象时，把候选里的 `object` 原样写进 `platform_extra`（抖音 `challenge`、视频号 `activity`）。活动常有时长、首发、必带话题等要求，候选里写了的要告诉用户。完整做法（每周活动清单、发布前怎么问）还是待办，等用户定。
2. **存档**：`archive DIR`。达芬奇当前开的不是本项目时命令会停下并提示；先问用户，同意后加 `--switch`（先保存用户的工程，切到片子自己的项目库做，做完切回原来的库、工程和时间线）。
3. **画面验收**：`archive-stills DIR`（同样，开着别的工程要加 `--switch`）出“存档恢复工程 vs 成片”对比图，人看图确认一致后，在 `04_达芬奇归档/<时间>/归档验收.json` 写 `visual_review_required: false` 和 `visual_review`（抽了哪几秒、结论）。不能凭结构核对通过就填。
4. **封存**：`seal DIR`（成片、三比例封面、字幕、资料快照进交付包）。
5. **预检**：`upload DIR`。只检查、不上传；看 `state: precheck_passed`。打印【注意】项目名和发布标题不一样时，先问用户要不要 `rename`。
6. **上传**：`upload DIR --execute`。用户在这次对话里已经说了“上传”并选好账号，就直接执行，不再问。
   - **传素材有进度、有时限**（2026-11-13）：每个文件先打印“开始传：文件名（大小）”，之后每分钟一行“还在传…已 N 分钟”，传完报用时；几个 GB 的成片要传很久，放后台跑、看到这些行就是在正常传。单个文件最多等 6 小时，其他命令最多等 5 分钟，超时会中止并说明原因（确实需要更久：环境变量 `THINKCUT_YXER_UPLOAD_TIMEOUT`、`THINKCUT_YXER_TIMEOUT`，单位秒）。传素材超时后回执停在 `uploading`，修好网络同样的命令再跑一次；**存草稿那一步超时算结果不明确**，按下面“重传、去重和安全”第 2 条让用户先看客户端。
7. **核对并汇报**：读 `05_上传记录/<编号>/回执.json` 和 `00_合并草稿参数.json`，逐平台报封面尺寸、横版封面、原创、分类、话题数；在 Finder 里打开回执所在文件夹。说清楚是“草稿已存”，不是“已发布”。
8. **提示收尾**：汇报完问用户一句要不要做片子收尾（thinkcut-edit 第 7 步，`$AI/口播自动剪辑/skill/thinkcut-edit/references/片子收尾.md`）：写片子复盘，再走 thinkcut-feedback，把问题整理成反馈单直接交给“架构审查”（2026-11-22 起不在对话里逐条确认）。

## 各平台默认（每次都写，用户点名才改）

各平台封面比例、开关、分类、定时的默认写在这个 IP 的规矩文件「发布」一节（在 `配置档/<IP>/规矩.md`），每次照写。定时发布：**用户说了时间才加 `upload DIR --schedule "2026-11-23 20:00"`**（北京时间，至少 10 分钟以后）：程序把时间写进有定时字段的平台（抖音、快手、小红书、视频号、B 站），预检和回执里列出每个平台是“定时”还是“不支持定时，点发布即发”；不要手改 `项目.json` 的 `platform_extra.*.scheduledTime`。YouTube 没有定时字段，仍合在同一条草稿里，用户点发布它就发。

- 单个项目要改：`项目.json` 写 `platform_extra`，例如 `{"快手": {"allow_download": false}}`；横版封面写在 target 的 `horizontal_cover`。
- **所有平台合成一份草稿**：各平台先单独校验和试保存，全部通过后合成 `00_合并草稿参数.json` 只存一次，客户端里是一条“N 账号 · N 任务”，用户点一次发布。

## 重传、去重和安全

- 去重：资料、文件、各平台字段完全相同算同一次，已有成功回执就直接返回，不重复建草稿。**同一个标题已经存过草稿**、这次字段又变了，命令会停下：确认用户已在客户端删掉旧草稿再加 `--again "原因"`。
- 任何一次上传结果不明确（`draft_save_pending`、`draft_save_result_unverified`）时，所有上传都会停，`--again` 也不行：先让用户在客户端看，有没有那条草稿都核对清楚后，把那份回执的 `state` 改成 `checked_in_client`。核对过的那份也算“这个标题存过”：客户端里有那条草稿就不用再传；没有或已删、要重存，加 `--again "原因"`（2026-11-13）。重存时上次已传好、文件没变（按 sha256 比）、24 小时内传的素材直接用，打印“不重传：…”；用不了的先打印“要重传 N GB（原因）”再传——事先别跟用户说“素材不用再传”，以这行输出为准（2026-11-21）。回执停在 `uploading`（存草稿之前就失败了，比如传素材断网、平台校验没过）不算不明确：修好原因后同样的命令再跑一次会接着传，已传好的素材不重传。
- 草稿**只能新存，不能改**。要改就重存一份，旧的由用户在客户端删。用户说“我把草稿都删了，重新上传”时用 `upload DIR --execute --again "客户端已清空"`。同一条 `--again` 命令重跑不会多存一份（中断了会接着传）；之后真要再存一份，原因换个写法（如“第二次清空”）。用户删之前不要先存，免得新旧分不清。
- 只重存部分平台时，临时只开那几个 target，存完把 targets 全部关掉（`enabled: false`），防止下次误重传。
- 不要删空的 `.上传.lock`。
- `yxer-safe` 只把必要的环境变量（PATH、HOME、语言、临时目录等）传给蚁小二 CLI，服务器地址固定为官方地址（2026-11-13）。环境里设了 `YIXIAOER_*`、`YXER_*`、代理（`HTTPS_PROXY` 等）、证书或 `DYLD_*` 这类变量时一律不传，并在标准错误提示一句“已忽略…”；看到这句照实告诉用户。这台机器要靠代理变量才能上网时上传会连不上，届时停下问用户，不要绕过 `yxer-safe`。
- 发布状态查询：`yxer-safe query records --json --limit 20`（看 `publishSource` 是 web 还是 cli、`taskSetStatus`）。客户端显示“查询失败”只是状态没取回，不一定是发布失败。

## 两种草稿的区别（用户问“能不能先放待审核”时这样答）

| | 蚁小二草稿（默认） | 平台草稿 |
|---|---|---|
| 在哪 | 只在蚁小二 | 推到各平台后台 |
| 发出去之前能不能改 | 能，在蚁小二客户端改（CLI 改不了，只能重存） | B 站、视频号是真草稿，能在平台后台改；YouTube 是私密视频；快手、小红书只能私密；**抖音没有草稿和私密，会直接公开** |
| 额度 | 不消耗 | 每平台一次 |

平台草稿要走 `yxer publish`，安全入口禁止；用户明确要求时先说清上面的风险，同意后再改规则。蚁小二没有单独的“待审核”状态。
