# 视频项目管理

本项目由人和 AI 共同维护。只维护标准目录、本地项目资料（项目.json）、归档和蚁小二内部草稿。不使用飞书文档。

- 文件夹名字与 `项目.json` 的 name 必须完全相同；修改名称时先列出差异，不静默改名。改编号/名称用 `project.py rename`，不手动改文件夹名。
- 做完的项目用 `project.py finish` 移进 `<片子文件夹>/finish`，要接着改先 `reopen` 移回根目录。
- 首页（审片台首页）右键改名、移到“做完的”、移到回收站调的是同一套 `rename`／`finish`；没登记过达芬奇库的片子传 `library=False`，不碰库列表（2026-11-24）。
- 项目规范见 `skills/thinkcut-project/SKILL.md`；上传见 `skills/thinkcut-upload/SKILL.md`。
- **在开发版改（2026-11-24 用户定：开发和使用分开）**：改本文件夹一律在开发版 `<开发版目录>/视频项目管理` 里做，不直接改使用版 `<程序目录>/视频项目管理`（用户做片子用的那一份，只在发版时才变）。下面的占位、测试、存档都在开发版里做；存档后使用版还没变，要让用户用上，由“架构审查”在用户同意后发版（开发版根目录 `python3 bin/release.py release --note "…"`，做法见根目录 `架构审查交接.md` 第 1b 节）。本文件和各说明里写的 `<程序目录>/...` 都是使用版的路径，在开发版干活时改的是开发版里同一个相对位置的文件。
- 修改本文件夹：先用 `python3 ../bin/placeholder.py`（程序目录 `bin/` 下的占位小工具，2026-11-21 起） 建占位：`take "修改人：改什么"`（它说“还有效”就停下；说“已过期”会自动接手，接手后先看有没有对方留下的未存档改动）→ 改 → `python3 -m pytest -q bin/test_project.py` 全部通过 → 根目录 `VERSION` 改为 `YYYY-MM-DD.N`、根目录 `CHANGELOG.md` 追加一句（全家一份，2026-11-24 起；本文件夹的 `CHANGELOG.md` 不再追加）→ 提交（整个程序目录一个仓库） → `release` 放掉占位（这时使用版还没变，发版后才用上）。
- 正式发布始终由用户在蚁小二客户端确认。禁止调用 `yxer publish`，包括以平台草稿代替蚁小二内部草稿。
- 凭据放当前 Mac 的登录钥匙串。Codex、Claude 都使用 `yxer-safe`；禁止写入 API Key 到项目、Skill、shell 配置、日志或普通 CLI 配置。
- 新项目使用标准目录。已有项目先读取并分类；未经具体清理授权，不删除、覆盖或移动原始文件、手调结果、旧工程和备份。
- 原始素材默认保留。定稿归档必须包含时间线依赖的媒体；恢复检验通过后才能讨论删除过程文件。文件名带“临时”“中间”不代表未被引用。
- 原始素材按A roll、B roll、音乐分类，命名为“内容_用途_序号”加原扩展名。先核实内容，不凭原名猜用途；维护01_原始素材/素材清单.json和素材目录.md，保存原名、新路径与摘要。已有媒体改名先核对工程引用，归档媒体和旧交付包不跟随批量改名。
- 最终视频必须以 `YYMMDD_项目名` 加原扩展名命名，使用 UTC+8 导出完成日期；复制、封存和上传保留此名。历史成片核实原始导出文件的修改时间，不使用整理副本的时间，不猜时间。
- 调整标题、简介等正文时遵守用户的 Claude 写作分工；整理既有内容、字段、模板和技术说明不另写宣传文案。
- 不修改另一个共享工具的规则或代码。需接入现有自动剪辑项目时遵守那个项目的 AGENTS.md。
