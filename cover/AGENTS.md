# 封面（`cover/`）：给 Codex 与 Claude Code 的说明

这里是 NAS 上集中维护的封面能力（脚本、Skill、字体、画风参考），不是成品目录。两台 Mac 共用这份代码，成品放在各自机器上。

**做封面**：用户说"做封面"或给视频标题要封面时，完整读取 `skill/thinkcut-cover/SKILL.md` 并严格照做，用户不必点名 Skill。风格和排版已经定稿，不要自行改动。

**接入新 Mac**：在本目录运行 `bash bin/setup_mac.sh`。它会检查 Python、Pillow、numpy、宋体、`codex` 命令，并把 Skill 链接到 `~/.claude/skills/thinkcut-cover` 和 `~/.codex/skills/thinkcut-cover`。首次使用前，本人要运行一次 `codex login`，这一步不能自动完成。

**从 shell 启动 Codex 驱动的运行**（`gen` 命令）：始终用 `< /dev/null` 关闭标准输入，后台运行也一样。

## 修改本共享能力：占位与存档

**在开发版改（2026-11-24 用户定：开发和使用分开）**：改本文件夹一律在开发版 `<开发版目录>/cover` 里做，不直接改使用版 `<程序目录>/cover`（用户做片子用的那一份，只在发版时才变）。下面的占位、测试、存档都在开发版里做；存档后使用版还没变，要让用户用上，由“架构审查”在用户同意后发版（开发版根目录 `python3 bin/release.py release --note "…"`，做法见根目录 `架构审查交接.md` 第 1b 节）。本文件和各说明里写的 `<程序目录>/...` 都是使用版的路径，在开发版干活时改的是开发版里同一个相对位置的文件。

用 git 存档。用户是非技术人员，git 操作由 AI 代做，并用中文汇报。只用本能力做封面、不改代码或文档时，不受本节约束。

**改之前先占位。** 修改任何文件之前，用占位小工具建占位：`python3 ../bin/placeholder.py take "修改人：改什么"`（程序目录 `bin/` 下，2026-11-21 起；它会记下是哪台 Mac、哪个会话）：
- 它说“占位还有效”：别的会话正在改。告诉用户里面写的修改人和修改内容，然后停止，不碰任何文件。
- 它说“占位已过期”并接手（建占位的会话已经不在了，或仓库 30 分钟没有任何改动；2026-11-21 用户定：过期的占位直接接手，不用等用户确认）：旧占位会自动挪进回收站。接手后先运行 `git status`，有对方留下的未存档改动就对着反馈单逐条审，对的留、半截的补完，单独存档，不混进本次存档，并告诉用户。
- 没有占位：直接建好。再运行 `git status`，发现不属于本次的未存档改动，要先告诉用户，不要混进本次存档。

**改完后存档。** 先运行 `bash bin/run_tests.sh`，显示"全部测试通过"才能继续：
1. 根目录 `VERSION` 改为 `YYYY-MM-DD.N`（当天第 N 次；2026-11-24 起全家一个版本号），在根目录 `CHANGELOG.md` 末尾加一句修改记录（本文件夹的 `CHANGELOG.md` 是合并前的记录，不再追加）。行为有变化时，同步更新 `SKILL.md` 和 `README.md`。
2. 运行 `git add -A`（整个程序目录是一个仓库，存档一次就把改到的各文件夹一起存了），核对暂存区里没有成品、缓存、钥匙或占位文件，然后执行 `git commit --author "修改人 <none@local>" -m "MM-DD 修改人：一句话中文说明"`。
3. `python3 ../bin/placeholder.py release` 放掉占位，告诉用户新的版本号，并说明这时使用版还没变、发版后才用上。

测试没通过就不存档，说明情况，由用户决定继续还是放弃；放弃时只恢复本次的改动。无论结果如何，最后都放掉本次的占位（`release`），不动别人还有效的占位。不得改写或删除已有的存档历史。用户说"退回到某个版本"时，用 `git revert` 生成新的存档，不用 `reset --hard`（在开发版做，再发版；要把使用版整个退回上一次发版之前，用开发版根目录 `python3 bin/release.py rollback`）。
