# 章节导航（`chapters/`，thinkcut-edit 第 5 步）

入口说明是 `SKILL.md`。只由“架构审查”会话改；做片子的会话不改，问题走 thinkcut-feedback 反馈单。

**在开发版改（2026-11-24 用户定：开发和使用分开）**：改本文件夹一律在开发版 `<开发版目录>/chapters` 里做，不直接改使用版 `<程序目录>/chapters`（用户做片子用的那一份，只在发版时才变）。下面的占位、测试、存档都在开发版里做；存档后使用版还没变，要让用户用上，由“架构审查”在用户同意后发版（开发版根目录 `python3 bin/release.py release --note "…"`，做法见根目录 `架构审查交接.md` 第 1b 节）。本文件和各说明里写的 `<程序目录>/...` 都是使用版的路径，在开发版干活时改的是开发版里同一个相对位置的文件。
**改之前先占位**：用 `python3 ../bin/placeholder.py`（程序目录 `bin/` 下的占位小工具，2026-11-21 起） 建：`take "修改人：改什么"`。它说“还有效”就停下报告；说“已过期”会自动接手，接手后先 `git status` 看有没有对方留下的未存档改动。
**改完存档**：`bash bin/run_tests.sh` 显示“全部测试通过”→ 根目录 `VERSION` 写 `YYYY-MM-DD.N`、根目录 `CHANGELOG.md` 加一行（全家一份，2026-11-24 起；本文件夹的 `CHANGELOG.md` 不再追加）→ `git commit --author "修改人 <none@local>"` → `python3 ../bin/placeholder.py release` 放掉占位（这时使用版还没变，发版后才用上）。
`配置/` 是用户的样式预设（数据）：用户做片子时存在使用版的 `配置/` 里，发版不拦也不动它；要跟着存档时，由架构审查拷到开发版存档再发版。用户要求保存样式时用 `preset-save`，不覆盖已有名字。
