# 花字音效：写计划、安全距离、口播起点、自动人物压字

[SKILL.md](../SKILL.md) 的必守规则照样适用。命令都在工作台（`$AI/core`）下跑。

## 先读画面和标记，再写计划

```bash
python3 bin/fx.py snapshot --timeline '主时间线' --out '/本片/花字音效/snapshot.json'
python3 bin/fx.py markers --timeline '主时间线'
python3 bin/fx.py check '/本片/花字音效/snapshot.json'
python3 bin/fx.py still --timeline '主时间线' --frames 108100,108200 --out-dir '/本片/花字音效/静帧'
python3 bin/fx.py plan --validate '/本片/花字音效/plan.json'
# 已经 build 过、用户在达芬奇里手改过花字颜色时，加工作目录，手改后整条保留的花字不查颜色：
python3 bin/fx.py plan --validate '/本片/花字音效/plan.json' --work-dir '/本片/花字音效'
```

- 每轮计划、build、小修都重新读当前主线全部标记的名称和备注，不只循环旧 effects 台账；逐个和 `source_marker` 的 frame/name/note 对照。缺失、原文改变和未覆盖的标记必须报告。
- 交付清单逐个列“标记全文 → 实际花字/音效 → 轨道与起止范围”；没写入的不得称完成。
- 新做先看必要静帧，小修不自动导图；拿不准问用户；同类新样式先只做一个给用户看。
- 不把历史标记帧当作现有片段的位置，要结合当前片段、字幕或逐字时间。
- 遇到已有空文字只报告，不猜原文、不补字。
- `markers` 标准输出为 JSON，标准错误为中文清单；检查失败退出码 2。静帧只导出当前时间线，核对时间码和文件并恢复播放头。

## 计划字段

- 结构见 `engine/fx/testdata/plan_example.json`；样式、音效名取 `engine/config/fx_styles.json` 和 `sfx_favorites.json`。
- 区间为绝对帧 `[start,end)`；`source_marker.frame` 为标记相对帧，name 和 note 保留当前原文。
- `layer` 是逻辑层，同层不能重叠；实际轨道按最低可用轨分配。花字 `track`、每个 sound 的 `track` 可用已有正整数轨号或唯一轨道名覆盖；锁定、重叠或有后续片段时停止，不解锁用户轨。
- 文字颜色：只有白和强调色 `#64A9E8` 两个，登记在 `fx_styles.json` 的 `colors`（`white`、`accent`）。不写就是样式自带的白；要强调色写 `style.color="accent"`。不要用 `overrides` 的 `Red1/Green1/Blue1` 写颜色；计划指定的文字颜色不是这两个之一（只容极小的浮点误差）时，`plan --validate` 和 build 都报错停下，`--allow-unsafe` 也不放行。只查计划要写进去的颜色：用户在达芬奇里手改过、被整条保留的花字不查、不拦、不改回。
- ready 计划每项都要有主体框、`layout_approved=true` 和前置快照哈希；初次 build 的 `precondition_snapshot_sha256` 用 `engine.fx.ledger.digest(snapshot['timeline'])` 算；快照变了要重新核对计划。

## 安全距离

- `plan --validate`、build 演练和写入都检查文字外框。计划 `timeline` 填 `width` / `height`；离线校验可加 `--snapshot '/本片/花字音效/snapshot.json'` 读分辨率与字幕轨。build 用当前快照，并在保留手调后重新检查。
- 规则在 `engine/config/fx_styles.json` 的 `safety`：照片标签（photo_label）和大字（keyword）四边留短边的 3%，其他 5%；避开整条字幕轨的保留区，位置读不到时统一保留底部 20%。
- 字号：每种样式的 `default_size` 取任务08同字体/形态用户样本的稳定 Size 中位数；计划省略字号就用默认值。下限是默认值的 75%，动画最小值和片段缩放也要满足，不能用缩放绕过下限。普通 Text 按同字体 em 等大换算默认值及下限；未知字体先报错。
- 主体框：`anchor.subject_bbox=[左,下,右,上]` 是真实主体框，不要为消除报错虚构主体框。
  - `subject_kind="person"`：外框与人物重叠不超过外框面积 15%。
  - 手机、照片或未注明类型：保留半个字高间距，不压在主体上。
  - 只有用户明确批准的旧计划 `overlap_ok=true` 可豁免未注明类型主体的间距。照片标签默认 `overlap_ok=true`（显式 false 仍保留）；`subject_kind="photo"` 且 `overlap_ok=true` 时，文字外框底部最多 35% 轻压照片顶部；仍要避开另一张照片、手机、边缘、字幕区和字号下限。
  - 同屏另有照片或手机时，可在 `anchor.avoid_bboxes` 填额外真实外框数组，统一保持半字高间距；移动建议也避开它们，不能把标签从一张照片挪到另一张照片上。
- 违规时列出效果、原因、移动建议与可选做法，标“需要用户决定”；不自动缩字。plan 校验不通过；build 默认跳过违规效果及其音效、其他照常，全部违规时不写入。操作记录和审片清单保留待决定项。
- 用户接受不安全布局后才用 `--allow-unsafe` 强制写入（任务已授权该选项时不重复确认）；输出仍保留违规和强制记录。缺字体、字形或分辨率等无法估算的情况不会被它掩盖。
- 外框按本机 `~/Library/Fonts` 的字形边界/字宽、上下伸、对齐、片段 Pan/Tilt/Zoom、动画最大字号、阴影/描边计算。估算器支持 `style.engine` 为 `Text+`（默认，Size 比例）或 `Text`（1920 像素参考宽下的字号）；build 只写 Text+，不能把普通 Text 的字号直接用于 Text+。当前写入用居中；显式 `horizontal_align` / `vertical_align` 可描述普通 Text 的左/中/右、上/中/下/基线；未校准的 Text+ 对齐枚举拒绝估算，不能猜。

## 音效规矩（程序会查）

- 每个效果最多一个音效，从花字起点开始。
- **2 秒内不超过两声**：全片按音效起点算，任意 60 帧（29.97 fps 的 2 秒）内有三声或更多就算违规，报出是哪几个效果、各在第几帧、用的哪个文件。程序认不出“镜头”，按全片任意 2 秒查，比“一个镜头内”更严。
- **同类事件全片同一个声音文件**。“同类”的口径：音效自己写了 `event`（如 `"event":"划掉"`）就按它；没写就按“花字的 `kind` ＋它是本组里第几个带音效的”（组＝`list_group`，没有就 `group_id`）。所以连续入场“咻 → 弹出 → 点击”、对比标签左右两声这类同组内按顺序换声不算违规；不同组的同一位置换了声音才算。确实是另一类事件（拍照、划掉、划线…）就给那个音效写 `event`。
- **用户否掉过的音效不用**（2026-11-22）：`engine/config/sfx_favorites.json` 的 `blacklist` 里的文件（现在是“唰音效刷出标题.mp3”，用户三次否掉）选到就算违规，同样 `--allow-sounds` 才放行。
- 违规时和安全距离一样：列出问题和可选做法，标“需要用户决定”，不自动删改音效。`plan --validate` 不通过；build（演练和写入）停下不写，退出码 2。用户听过认可后才用 `--allow-sounds` 照做（2026-11-13 用户定：和版面的 `--allow-unsafe` 分开，各放行各的），输出里保留违规记录（`sound_rules.forced`）。用户在达芬奇里动过、不会重放的音效不计入。
- 只按帧数和文件名查，听感仍要用户试听。

## 口播起点与连续清单

- 普通口播花字从对应口播首字出现帧开始，标记只提示附近位置。
- 计划 `transcripts` 写“当前 A1 源完整路径 → 已有逐字 JSON 路径/对象”，不重新转写。效果 `speech.text` 写对应原话（默认查花字文字）；`speech.search_start/search_end` 限定找词区间（默认计划起止前后 90 帧）。按当前 A1 源区间映射；缺逐字时退回字幕并在清单注明“估算”；两者都找不到就停止，不能拿标记帧冒充。纯画面补充写 `speech.mode="visual"`。
- 已有花字手调过的起止优先保留，小修不重新自动排时。
- 多行累积清单：各行给相同 `list_group`、样式、位置和可选 track，按每行首字排列；程序生成同一轨首尾相接的连续状态标题（“第一行 → 前两行 → 全部三行”），新行才配本行音效。`list_line` 存本行原文；未出现的行用空行预留位置，整组按完整清单统一位置，免得切状态时旧行跳动。不得每行堆一条轨；同轨标题无论 layer 是否不同都不能重叠。
- 普通人物花字默认按真实人物框找旁边留白，再用遮罩核对；不自动居中盖脸或缩字。明确位置用 `anchor.placement="explicit"`，字幕替代或顶部居中分别用 `subtitle_replacement` / `top_center`。章节用 `kind="chapter"`，不用标点，改空格或换行。
- 先输出可核对的计划：

```bash
python3 bin/fx.py plan --validate '/本片/原计划.json' --snapshot '/本片/快照.json' --prepare-out '/本片/准备计划.json'
```

新批次 build 也会做这一步准备；演练先核对起点、估算说明、轨道与真实布局再执行。

## build 自动人物压字

- 普通人物花字先执行旁边留白；真实遮罩有覆盖时继续移到零覆盖，挪不开就停止，不回退盖脸。明确指定位置、照片等效果才用下面的遮挡阈值。
- 默认开 `fx_styles.json` 的 `matting.enabled`；最大遮挡比例 `matting.max_coverage` 默认 20%。程序先判断 V1 可见区间，再用 RVM 真实遮罩决定；build 演练只报告“待计算”，apply 才生成。
  - 人物覆盖 0：不放抠像层。
  - 0 到阈值：人物在字前。
  - 超过阈值：向远离人物的方向找最近安全位置，不缩字；找不到就保持原文字盖在人上，并在操作记录和审片清单注明。
  - 同屏有回退花字时，共享人物层避开其区间，免得别的花字的抠像层又盖住回退文字。
- 矩形人物 15% 规则用于独立 plan 校验；自动 build 用真实遮罩，仍执行边缘、字幕、照片、手机和字号规则。
- 读 V1 源区间；上层有可见视频/照片的区间不抠；变速、未校准的旋转/透视/裁切/动态缩放不猜，记为“无抠像回退”。
- 环境：`~/Library/Application Support/ThinkCut/环境/thinkcut-matting/`（NAS 上程序目录 `环境/` 的运行副本，缺了运行 `bash $AI/bin/sync_env.sh`），setup_mac 自动准备，doctor 报缺项。
- 输出透明 ProRes4444、时间线分辨率，保留原 RGB，调 ZoomX/ZoomY 及 Pan/Tilt 补偿输入缩放；Straight Alpha、Full Range、Input LUT/色彩空间和 CopyGrades 都读回。
- 缓存键＝源路径/大小/修改时间、源区间、模型及输出版本/分辨率；缓存、成品和日志只放本片工作目录 `抠像/`；抠像时用完即删的原始帧临时文件放这台 Mac 的系统临时目录（`thinkcut-rvm-frames-` 开头的文件夹，不写 NAS），下次开始抠像时自动清掉上次没删完的。
- 解码、推理、转码三阶段串行，一次只一个 ffmpeg 进程；CPU 推理、ffmpeg 解码/编码及滤镜最多 4 线程（减轻同机使用负担）；不生成临时 PNG，临时 raw 在程序私有临时目录，用完清理。
- 主线最高轨「人物抠像」在原生花字之上、同时出现。重建只非波纹替换本程序认领且状态未动的层；用户移动、删除或改了可读属性时停止并保留现场。
- 审片底图副本停用内部人物层，在审片 V2 直接复制人物素材、变换和调色，避免重复合成；清单列出每项覆盖比例、移动与回退原因。不需要用户手工抠像、导入或摆轨。
