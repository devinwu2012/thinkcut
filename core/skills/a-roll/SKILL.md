# AI 口播剪辑

> **路径和 IP**（2026-11-24 配置档）：下文 `$AI` 是程序目录：`AI=$(cd -P ~/.claude/skills/thinkcut-edit/../../.. && pwd)`（技能链接指着的使用版；在开发版试验时换成开发版目录）。`<片子文件夹>`、`<试验田>`、`<回收站>` 是这个 IP 配置的位置，用 `python3 "$AI/bin/thinkcut_config.py" show --key 片子文件夹` 查（默认是程序目录旁边的 `<IP 名>视频/`、`<IP 名>试验田/`、`#recycle/`）。做哪个项目先读它所属 IP 的规矩：`python3 "$AI/bin/thinkcut_config.py" rules --project <项目根>`（在用户配置档 `<IP>/规矩.md`；用户配置档默认是程序目录旁边的 `ThinkCut配置档/`，`python3 "$AI/bin/thinkcut_config.py" where` 查），和这里冲突时以那份为准。


## 必守规则

1. **用户改过的素材整项不再改**（2026-10-17 用户：“只要是我改过的素材都不要再改了。”）。开始前读 `core/AGENTS.md`（硬性边界和「用户手工定稿保护」全文）照做。
2. 实际剪辑前必须读 [口播剪辑工作规范](references/editing-workflow.md)；仅转写时读 [仅转写.md](references/仅转写.md)，不执行剪辑步骤。
3. 新达芬奇项目**不先问，按默认直接做**（2026-11-22 用户定“先做出来再改”：“按照AI的想法直接做就行了，不用来问我，等做完了我边看边改”；取代原来的“先确认工程名、导入方式、时间线格式再建项”）：工程名＝项目文件夹名，素材按原名导入，画幅用户给任务时说了就用他说的、没说用 3:4；这几条假设在交给用户时说一句。画幅只改目标时间线，不改项目设置；不套 LUT。
4. 审核状态生成后不再重新生成，绝不删审核状态文件“重来”。唯一的回退是 `reopen`（2026-11-22 261122 反馈单 新12，见下面“审核一旦生成”）：只在用户还没在口播精剪栏动过这一版时可用，旧的挪进备份不删。
5. **人工气口精修不能跳过**；自动精修只管停顿长度，不等于听审。建审核线前成片上 ≥0.27 秒的字间停顿必须为 0。
6. 字幕校对（`corrections … --done`）是导入达芬奇前的必做步骤；校对完成前不打开审片台。
7. 原片换成同帧数新版只能走 `replace-source`，不绕开工具手改；帧数不同或声音错位就是新口播，用新项目。
8. 未通过读回核验不得报告成功；程序核验和用户听审分开说；不渲染。

剪口播、修气口、删重复、修吞字、跳切都用本 Skill，不必用户点名。可以用 Fusion（跟踪、抠图、背景模糊），普通花字仍优先 Text+，见 AGENTS.md。

## 新项目：按默认直接做，不先问

- 接到新的达芬奇剪辑项目，按 [工程准备](references/editing-workflow.md#工程准备与确认) 的默认直接建项、导入和剪辑，不停下来问工程名、导入方式、时间线格式（2026-11-22 用户定“先做出来再改”）；用户给任务时说过的照他说的。画幅每个项目按它自己的来（用户说的，没说就 3:4），不沿用上一项目的。改现有项目照旧保护用户手动调整。
- 工程名以项目文件夹名（`项目.json` 的 name）为准；`01_原始素材` 下的 A roll、B roll、音乐按原名导入主媒体夹。**不套 LUT**（2026-10-24 用户定）。
- 画幅：16:9 沿用新项目默认；4:3 为 2880×2160，3:4 为 2160×2880，两者在时间线内关闭“使用项目设置”。导入及旧交付程序的限制见上述规范。

## 完整剪辑：`python3 bin/edit_project.py <动作> --project-dir <项目文件夹>`

标准顺序：**prepare → 写选择 → finish → 气口精修与映射重建 → 字幕校对（corrections … --done，必做）→ serve 打开审片台“口播精剪”栏给用户改 → 用户点“保存到达芬奇”（或 deliver）**。用户只想在达芬奇里看时，校对并 `--done` 后直接 deliver，不开审片台。

审核一旦生成（`审核/review_v2_state.json` 存在）：之后对选择的修改让用户在审片台“口播精剪”栏里改。AI 发现自己写的 `review_decisions.json` 选错了（如删错位置）、用户还没在口播精剪栏动过这一版时，**不用另开 `_第2次` 目录**（2026-11-22 261122 反馈单 新12）：改好 `review_decisions.json` → `reopen`（这一版审核挪进 `审核/review_state_backups/回退前_<时间>/`，不删；字时间换回对齐原样，字编号不变）→ `finish` 重新生成、精修、出校对单 → 照常人工气口精修、字幕校对（回退前写过字幕纠错的，按 reopen 打印的命令 `corrections --file …` 写回再核对）→ 打开审片台。已经保存到达芬奇的主线不动（留旧版），再保存是一条新主线。用户已经在页面上动过（文字剪辑器改过、改过卡片取舍、写过备注、页面保存过）时 `reopen` 会拒绝，不丢用户的修改：在口播精剪栏里选中删错的字点“恢复”、选中真正要删的字点“删除”。真要整条从头重选，才用新项目文件夹（可复用原片旁已有识别结果，不重复计费）。

1. **先 1.2 倍速＋人声处理**（2026-11-01 用户定；用户说这条不加速才加 `--speed 1`）：prepare 前跑 `python3 bin/speed_voice.py <原片>`，输出到 `02_制作/口播转码/`（原片不动），再拿输出文件 prepare。
   - 画面和声音一起 1.2 倍速，恒定 29.97；人声 高通→轻降噪→压缩→**固定增益**到约 -12.5 LUFS＋限幅 -1.5 dBFS。
   - 做完每 10 秒测一次响度，有一段和全片中位数差超过 2 LU 就报错不出片（2026-11-12《水电阶段》：旧 loudnorm 让开头 30 秒小了 10 dB）。
   - iPhone HLG/PQ 原片自动用苹果系统取显示帧算颜色曲线再转，颜色和 Mac 上看原片一致、不发灰（曲线存 `<输出名>_苹果显示曲线.cube`）。
   - 自己转码时也必须让声音和画面都从 0 开始（手机原片音轨常晚几百毫秒：ffmpeg 音频先加 `aresample=async=1:first_pts=0` 再变速），否则 prepare 会停；错位会让识别时间和画面差十几帧、整片刀口偏早吞字（2026-10-23）。
2. **prepare** `--video <转码后的口播>`：记录原片显示分辨率（含手机旋转）；检查恒定 29.97 fps、单音轨、声音与画面同时从 0 开始和对齐依赖后，才调用付费识别（豆包极速版 `volc.bigasr.auc_turbo`，单次 ≤2 小时、≤100 MB），然后后台开始声学对齐（日志 `审核/align.log`）。项目里已有识别结果校验后复用、不重复计费；另一台 Mac 的结果也可复用（按声音比对）。已初始化的项目不会被覆盖。
3. **选择**（对齐在后台时同时做）：通读 `审核/sentence_units.json`，判断重录、残句、现场交流；保留独有信息，重录取最后一遍完整正确的表达，不确定就保留。有文案时据此判断有效版本，但说法不同处保留现场原话。写 `审核/review_decisions.json`，示例：

   ```json
   {"reviewer": "Codex：单次全文语义审核", "limitations": ["接缝听感需用户听审"],
    "cuts": [{"unit_id": 0, "char_start": 0, "char_end": 12, "text": "我用了很多年的苹果手机，", "reason": "重录：保留后一遍完整表达", "replacement_ids": [4]}]}
   ```

   `unit_id` 是 `sentence_units.json` 里的 `id`；`char_start`/`char_end` 是该句 `text` 里从 0 开始、不含结尾的字符位置，`text` 必须与这段原文一字不差；删整句就从 0 到整句长度；`replacement_ids` 是保留的那一遍的 `unit_id`（没有就 `[]`）；什么都不删时 `cuts` 为 `[]`。`reviewer` 如实写审核方式，一次判断不得写成两次。不改写正文。
   - **删口吃、重复字**（2026-11-22 261122 反馈单 新12：删“我我们”的口吃写成了句首“我们从头跟到尾”的“我”，删成“们从头跟到尾”）：`char_start` 数到真正连着重复的那一处，不要拿这个字第一次出现的位置。`reason` 写“口吃／重复”、删 1–3 个字时，程序查删掉的字紧挨着的前面或后面还有一模一样的一份，没有就停下并列出句子里连着重复的位置。所有删 1–3 个字的条目，`review`（finish 里）都打印 `删字核对 …[删掉的]… 删后读作：…`，逐条读删后的句子通不通，不通就改选择、`reopen`、再 finish。
4. **finish 与气口精修**（项目不用加 `--script`：finish 自动取项目文案 `03_成片/<项目名>.md`（2026-11-22 起；没搬的老项目读 `02_制作/` 那份）里的“口播正文”对稿，标题、封面文字、`###` 小标题不算；文案里没有「## 口播正文」小标题时会停下，按提示补上再跑。别处的文案才加 `--script <文案.txt>`，Word/飞书先转纯文本）：
   - finish 等对齐完成，生成可逆初剪（默认句内不剪、句间紧剪；对不准的字回退到豆包原始字词时间，被拆开的整词如“五百”合并为整词；选区写错会报出第几条、怎么改），做文案对照，生成字幕校对稿，输出中文摘要。
   - 再自动按实际音量精修停顿（`refine`）：整片保留原声，字头字尾按实测音量保护，句间与删除重录接口最多留 4 帧，句内静音超过 4 帧收到 3 帧，字边按音量最多保护 4 帧（2026-11-01 收紧），记在 `审核/气口精修.json`。一帧算“有声”要音量过门限、**而且** Silero 语音检测的人声概率 ≥0.5（2026-11-22 用户定，底噪略高的停顿也能收掉；人声概率由对齐环境的 Python 算，存 `审核/气口人声概率.json`）；对齐环境没有 silero-vad、算出错或超过 5 分钟，就照旧只看音量，打印“这次没用上语音检测（原因）”，不停下。已精修过会跳过；口播精剪栏删句、恢复后接缝自动跟着改，其余裁剪不动（细则见工作规范）。
   - **然后人工气口精修**（2026-11-01《别墅地下室防水》跳过了，用户两次听出“气口不干净”）：按 [气口精修与手改学习](references/editing-workflow.md#气口精修与手改学习) 检查整片句内短语间停顿、句首句尾及重录接缝，删掉已核实的多余气口，重建统一音画/字幕映射，再进第 5 步；拿不准的保留并具体列出。
5. **字幕校对（导入达芬奇前必须完成）**：finish 已生成 `审核/字幕校对.json`（每句保留下来的字幕、字编号；有文案时附 `script_candidates`），重新生成用 `proofread`。逐句通读并按其中 `rules` 改：
   - 有文案时数字、型号、品牌、专有名词按文案写法（如“X五百”→“X500”、“叉三百”→“X300”）；没有文案时按上下文改同音字、错字、的/得；识别和实际说的完全不一样时按说话人原意改写；现场换了说法、临场加话以实际说的为准，不套文案。
   - 每句的 `words` 是 `[字编号, 原字(, 已改写法)]`；一个字编号可能是整词（如“五百”），`before` 必须写这个整词。改动存成 `审核/字幕纠错.json`：

   ```json
   [{"id": "u4c21", "before": "五百", "after": "500", "reason": "型号按文案写法"},
    {"id": "u30c16", "before": "脚", "after": "焦", "reason": "同音识别错字：长焦"},
    {"ids": ["u3c1", "u3c2"], "before": "Mac Studio", "after": "Mac Studio", "reason": "跨词整体纠错，保留英文空格"}]
   ```

   - 连续多字用 `ids` 按原顺序列出同一句相邻编号，`before` 写覆盖的原文，`after` 写完整替换（含所需空格），不拆改英文 token 拼空格。范围整体显示并保留所有字编号与时间；只删选范围内部分字后，要撤销该范围纠错并重新校对。after 不能为空；撤销以前的某处改正写 `{"id": "…", "remove": true}`。
   - 用 `corrections --file 审核/字幕纠错.json --done` 写入并标记完成；没有要改的也要 `corrections --done`。新项目未标记前，交付和口播精剪栏“保存到达芬奇”都会被拒绝。校对完成后再 `serve` 打开审片台。用户之后在口播精剪栏里恢复了被删的话，新出现的字幕要重新 `proofread`、校对、再 `--done`，否则不能导入。审片台开着也可直接写入；口播精剪栏提示状态已更新时刷新即可。
   - 用户纠正过的人名、品牌、型号，校对完顺手追加到仓库根目录 `词库.txt` 并提交（按 AGENTS.md 的词库流程）。交付前把字幕里的主播名、品牌名逐个对一遍 `词库.txt`（2026-10-29：《老房烟道》主播名曾交付成同音错字）。
   - 拿不准的改动和 `possibly_missing` 里的句子告诉用户。用户也可在口播精剪栏选中一个字点“改字幕”。
6. **换源**（2026-11-12《水电阶段》）：口播源换成同帧数的新版（重新调色、重做声音）后，口播精剪栏和 deliver 会报“原片已改变”。先 `stop` 停剪口播后台，再 `replace-source --video <新口播> --old <换源前的旧文件>`（新文件可以放原路径，旧的改名留着当 `--old`）。
   - 它核对帧数/帧率/尺寸、声音 5 处和转写时对齐（偏差 ≤40 毫秒）、画面 8 处和旧片同一帧，全过才把来源基线换成新文件；审核状态、删句、字幕校对全部保留，记在 `转写/换源记录.json`；之后口播精剪栏删句、deliver、SRT 照常。
   - 没有旧片时可不给 `--old`，但画面只核对帧数，要自己确认是同一条口播。
   - 换了路径：下次 deliver 把新文件导入媒体池（旧主线不动）。路径没变而达芬奇还显示旧画面：对素材“重新链接”或重开工程。
7. **审片台“口播精剪”栏**（2026-11-22 用户定：原来单独的审核网页并进审片台，“用改文字的方法做剪辑”，以后改文案前后顺序也在这里）：`serve` 打开这个项目的审片台、停在“口播精剪”栏（`finish` 末尾自动起的那次也是）；口播精剪栏上半改标题、封面文字，下半是文字剪辑器（删句、恢复、拖小句调顺序、改字幕、分段、撤销重做、预览、保存到达芬奇）。还没 `init` 自动剪辑的项目目录时审片台照样能开，只有“口播精剪”栏能用；标准项目的审片台数据放 `02_制作/自动剪辑/审片工作台/`，init 之后接着用。直接打开剪口播后台的地址只提示“已并入审片台”。
   - 剪辑器的后台还是本仓库的 `review_v2_server.py`（一个项目一个进程，程序更新后空闲时自动重启）：审片台按需起（`serve --backend`，不开浏览器）并把页面请求转给它；`status` 查看、`stop` 停止后台（审片台下次操作时自动再起）。审片台找不到时设 `THINKCUT_SKILL` 指到 thinkcut-edit。页面在 thinkcut-edit 的 `assets/审片工作台/文案剪辑.html`，说明见 thinkcut-edit 的 `references/审片工作台.md`。
   - 文稿分章（2026-11-13 用户：要像文章，一章一整段，自然段自己分）：`serve` 前 AI 通读保留下来的文字，按话题写 `审核/文稿分段.json` 的章节：`{"sections":[{"start":句编号,"title":"第一件：卫生间通风排味"}]}`（句编号看 `转写/sentence_units.json` 或字幕校对表的 unit_id）；一般是开场、每一件事、结尾，几分钟的项目 4–8 章。不写段落：口播精剪栏里每章就是一整段（首行缩进），用户点字按回车自己分段、按删除键合并（存在同一个文件的 breaks 里，只管排版，不影响剪辑）。没写章节时口播精剪栏按“第一个/第二件…”自动分章。 自然段不用 AI 分（2026-11-22 用户定：“不能一整个自然段……按照咱们写文案的时候是几个自然段”）：后台第一次给文稿时自动按定稿文案「口播正文」的自然段分一次（对不上、没有文案按字数在句末拆）并存进这个文件，用户之后用回车、删除键改。
   - 调顺序（2026-11-13 用户定）：口播精剪栏里每个小句（按逗号、句号等分开）下面有一条蓝色下划线，按住拖到别的小句前面或后面，记进撤销重做；预览、字幕、保存到达芬奇都按新顺序。挪动处停顿和原来一样长（两字之间的停顿从中间分开，各带一半），不打标记。只在还没配 B-roll 时用：配了 B-roll 的项目不能挪，挪过的项目交付时也会拦下 B-roll。
8. **deliver**（或用户在审片台口播精剪栏点“保存到达芬奇”）：
   - 经 MCP 在项目自己的达芬奇项目库（库名就是项目文件夹名，不用本机库）里打开/新建和项目文件夹同名的工程。
   - 建线前核对原片与目标帧率；默认帧率不一致且无法独立指定时，在建线前中文停止，不改项目设置。DRT 导入前后核对项目宽高/帧率，变了就恢复并记录，恢复失败就停止。
   - 按工程准备规范绑定原素材与时间线格式（只改时间线画幅），生成含字幕主线 `<版本>_主线_<月日-时分>_<编号>`（版本 v1、v2…：同一个 02_制作 里每重剪一次加 1，2026-10-23 用户定）；保存、关闭重开、读回核对音画偏移、链接、字幕和分辨率。
   - 保存前若主文件夹里本程序生成的旧主线被用户改过（片段、字幕或加了轨道），中文报错停止并提示先改名；调色、音量、缩放等查不出来，所以开始精修前就让用户把主线改名。主文件夹只留最新主线，旧版移入“历史版本”（不删；用户自建或改名的不动）。
   - 交付文件发布到 `交付/`，`审核/latest_delivery.json` 指向最新版。MCP 单次 90 秒超时。

其他：
- 项目定稿后可运行 `clean` 列出能重新生成的文件（对齐音频、预览缓存、旧日志与较早备份；交付包始终保留）及大小；告诉用户，同意后才加 `--yes` 删除。`交付/` 根目录只放最新的 SRT/DRT/DRP，旧版在 `交付/历史/`。
- 单步动作 `init`、`align`、`review`、`script` 仍可单独用（排查问题时）。
- 失败时 `edit_project.py` 输出“出错了 / 下一步 / 原始信息 / 完整日志”（`审核/错误日志.txt`），向用户转述中文部分。
- 项目 `审核/project_runtime.json` 设 `existing_project_only: true` 时只打开已有同名工程，找不到即停止。
- 配 B-roll、换备选、开 B-roll 原声或标露脸句：读 `skills/b-roll/SKILL.md`。

## 机器配音占位（没有口播录像、只有定稿文案时）

2026-11-22 用户定“先做出来再改”：“按照AI的想法直接做就行了，不用来问我，等做完了我边看边改”；同一段话：“如果……只有一个口播的文案，都没有这个A-roll，那它就机器生成人声做上去得了……我有了之后我再替换”。

- **什么时候用**：项目里没有口播录像（`01_原始素材` 里没有 A roll），但有定稿文案 `03_成片/<项目名>.md` 的「口播正文」。不问用户，直接配。
- **怎么做**：`python3 bin/doubao_tts.py --project <项目文件夹> [--format 3:4|9:16|16:9]`。它用豆包语音合成 2.0、默认音色“小何”（2026-11-23 用户听过试听后定）把口播正文按自然段念出来（`###` 小标题、`>` 备注不念），**命令自己先打印总字数和每段的字数、开头，再接着合成**（按字数收费，含标点；不用先跑 `--dry-run`、不用等人确认，2026-11-23；`--dry-run` 只算字数不花钱），做成黑画面＋配音的口播源 `02_制作/口播转码/机器配音占位_口播.mov` 和旁边的记录 `机器配音占位_口播.机器配音.json`（标着占位，带每个字的时间），接着自动 `prepare`（建 `02_制作/机器配音占位_口播_AI剪辑/`）并写好“什么都不删”的 `review_decisions.json`。
- **发试听**（2026-11-23 初稿模式实测）：`init` 之后把配音发到审片台配音试听栏：`workbench <项目文件夹> --publish 口播试听 --kind 试听 --files 02_制作/口播转码/机器配音占位_口播.mov … --draft --placeholder`。直接给这个 .mov，审片台自动抽出声音成 mp3，不用自己转。
- **不花识别的钱**：`prepare` 发现口播源旁边有机器配音记录，就用合成时给的字和时间，不调豆包识别；对齐、对稿、停顿精修照常跑。`审核/project_runtime.json` 记 `placeholder: {kind: 机器配音}`，后面的动画成片（thinkcut-edit `init`）读它。
- **接着做**：`finish --no-serve` → 通读 `字幕校对.json`（字幕就是文案原文，一般不用改）→ `corrections --done` → `deliver`。机器配音**不用** 1.2 倍速、不用人工气口精修、不用修音。
- **某一段没合成下来**：命令会停下说是第几段；合成好的段存在 `02_制作/口播转码/机器配音/`，同一条命令重跑只合成剩下的，不重复花钱。连不上、超时自动重试 3 次（中断的那几次可能已计费，会说明）；豆包明确拒绝（没开通、钥匙不对）不重试。
- **改了文案要重配**：还没建剪口播工程时直接重跑；已经建了，先把旧的 `机器配音占位_口播.mov`、`.机器配音.json`、`机器配音占位_口播_AI剪辑/` 挪进回收站再跑（合成过、没改的段照样复用）。
- **用户录了真口播以后怎么换**：真口播和机器配音的长短、节奏都不一样，**不能用 `replace-source`**（那只管同帧数换源）。按正常流程新剪一条：`speed_voice.py` → `prepare --video <真口播>`（新的 `<片名>_AI剪辑/`，主线版本号自动加 1）→ 选重录 → `finish` → 气口精修 → `deliver`；然后在动画成片那边 `init --force --aroll <新工程>` → `words` → `beats`（分镜的卡点按词找，会自动落到新口播的时间上）→ 重出动画和审核线。机器配音的工程和口播源留着不删。
- 钥匙只走 `doubao_credentials.load_key()`，不打印、不写进任何文件；离线测试 `bin/test_doubao_tts.py`（假回应，不真调）。

## 验收与汇报

- 预览、SRT、达芬奇时间线用同一保留区间；原片在操作中改变即停止。
- 区分程序核验（结构读回）与用户听审；说明待听的接缝、拿不准的纠错和漏念句。
- 涉及删除/恢复的界面测试只在隔离状态里做；性能数据分开提音、API 往返、对齐、预览和交付，不拿缓存复用速度冒充新调用。
- 换 Key 用 `bin/doubao_credentials.py` 的本机页面，只接受豆包语音新版控制台的 Key。
