# 本目录供 Codex 与 Claude Code 使用

## 用户手工定稿保护（所有工程、所有 Skill，2026-10-17）

**用户原话：“只要是我改过的素材都不要再改了。”用户手动制作或修改后的版本就是最终素材。**

- 适用于所有工程与所有制作 Skill，包括 A-roll、B-roll、字幕、花字、音效、图片、窗口、Fusion 节点及其参数。手动改过的整个素材／片段从批量修改、统一样式、重建、替换、清理和重新交付中排除，不能只保留几个改过的字段再重建它。
- 每次写入前以当前工程为准，对照上次 AI 写入记录辨认手改，并按片段 ID、源素材和当前范围记录保护清单。原本由 AI 创建也不代表可以继续接管；没有可靠基准或不能确定是否手改时，保留现状，不覆盖。
- 手工参考只供只读学习；不能修改参考本身，也不能用旧计划、默认参数或统一模板把手改版恢复成 AI 旧版。用户删除、替换、停用或拆掉的内容不得自动补回。
- 只有用户明确点名该对象并要求再次修改时，才调整其点名的内容，其他部分仍保留。“全片统一”“全部重做”“按这个模板”本身不授权覆盖手工定稿素材。
- 工具若不能排除受保护对象，就改用只处理已授权目标的局部方式；做不到则跳过该项，不能先整批覆盖再补回。写后核对保护对象没有变化；发现误改只撤销本轮造成的变化，不拿旧快照覆盖用户新改动。

这里是 NAS 上集中维护的 AI 口播自动剪辑能力（程序、Skill、豆包 Key），不是任何人的视频项目。

**读什么**：AI 剪辑先读剪辑总入口 `<程序目录>/studio/skill/thinkcut-edit/SKILL.md`，按它的步骤表选子 Skill；明确要剪口播时，读 `skills/a-roll/SKILL.md` 和 `skills/a-roll/references/editing-workflow.md`；配 B-roll 时，读 `skills/b-roll/SKILL.md`。写入达芬奇（任何分项）时，先查 `docs/达芬奇接口实测.md` 里已实测的接口行为。用户不必点名 Skill。接入新 Mac 时，运行 `bash bin/setup_mac.sh`（逐项检查，缺什么装什么：ffmpeg、Node、对齐环境与模型、达芬奇 MCP 与字幕组件、Skill 链接；Homebrew、Xcode 命令行工具、达芬奇本体需本人安装），再按 `python3 bin/doctor.py --summary` 的中文清单行动。只打开文件夹不会自动安装。

**硬性边界**
- **可以使用 Fusion（2026-10-23 用户：“……ai 工具可以用 fusion”；取代 2026-10-17 的禁止规定）**：跟踪（如花字跟随物体）、抠图、玻璃背景模糊、圆形窗口等需要 Fusion 的效果，可直接在 Fusion 里做，不必先问。做法：先复制需要的片段范围做成独立复合片段，在复合内制作，不在原片上直接加；新建节点显式设置 FlowView 位置、分开排布并清楚命名。普通静态花字仍优先用剪辑页原生 Text+／文本（剪辑页好改、不卡），只在需要 Fusion 才能实现的效果上用 Fusion。用户自己做的 Fusion 效果仍按手工定稿保护，保持原样，不改不删。
- 视频、转写、审核状态、达芬奇工程都放在各自项目目录（标准项目放 `<项目根>/02_制作/` 下：剪口播 `<片名>_AI剪辑/`、B-roll `B-roll_AI/`、花字 `花字音效/`；不是标准项目时默认原片旁 `<片名>_AI剪辑/`；已有旧目录继续用），不写进本目录，不复制原片进来。
- 豆包 Key 在这台 Mac 的钥匙串里（2026-11-25 起；老位置 `secrets/doubao_api_key` 照读并自动导入），只由 `bin/doubao_credentials.py` 读取；不得打印、转述、写入任何文档或存档。
- 完整剪辑只支持单音轨、恒定 29.97 fps；不自动启动达芬奇渲染；交付时间线须保存、重开、读回核验（口播交付经 MCP；B-roll 与花字用 DaVinciResolveScript 直连写入，同样保存关闭重开读回；花字音效的小修按 thinkcut-edit「花字音效」 Skill 只做必要确认，不保存重开）。
- 不伪造识别、时间戳或达芬奇核验结果；转写成功不等于剪辑完成；一次审核不能说成两次；原片改变时不重写来源基线，改用新项目；唯一例外是 `edit_project.py replace-source` 的同帧数换源（帧数、帧率、尺寸一致，声音时间和转写一致，给了旧片还逐帧抽查画面，全部通过才换，旧基线写进 `转写/换源记录.json`，2026-11-12 用户确认）。

## 修改本共享能力：占位与存档

**在开发版改（2026-11-24 用户定：开发和使用分开）**：改本文件夹一律在开发版 `<开发版目录>/core` 里做，不直接改使用版 `<程序目录>/core`（用户做片子用的那一份，只在发版时才变）。下面的占位、测试、存档都在开发版里做；存档后使用版还没变，要让用户用上，由“架构审查”在用户同意后发版（开发版根目录 `python3 bin/release.py release --note "…"`，做法见根目录 `架构审查交接.md` 第 1b 节）。本文件和各说明里写的 `<程序目录>/...` 都是使用版的路径，在开发版干活时改的是开发版里同一个相对位置的文件。

由“架构审查”会话维护，已用 git 存档。用户多为非技术人员，git 操作由 AI 代做并用中文汇报。只用本能力剪片、转写而不改本目录文件时，不受本节约束。

新经验不再写进旧的 `经验/待审/`（只在 NAS 上，不进 git）：随手记进项目 `02_制作/反馈记录.md`，收尾走 thinkcut-feedback 反馈单（2026-11-11 起）。

用户要求“写进 Skill / 写回规则”时，写进对应分项的 Skill 或其 references（thinkcut-edit「剪口播」、thinkcut-edit「配 B-roll」、thinkcut-edit「花字音效」）；总入口 thinkcut-edit 只负责分派，不写分项规则。

`词库.txt` 可直接追加（在开发版加，随下次发版到使用版），不用建占用文件、不用跑测试；加完提交一次即可：`git add 词库.txt && git commit --author="修改人姓名 <邮箱或 none@local>" -m "词库：加 …"`。

**改之前先占位。** 修改任何文件之前，用占位小工具建占位：`python3 ../bin/placeholder.py take "修改人：改什么"`（程序目录 `bin/` 下，2026-11-21 起；它会记下是哪台 Mac、哪个会话）：
- 它说“占位还有效”：别的会话正在改。告诉用户里面写的修改人和修改内容，然后停止，不碰任何文件。
- 它说“占位已过期”并接手（建占位的会话已经不在了，或仓库 30 分钟没有任何改动；2026-11-21 用户定：过期的占位直接接手，不用等用户确认）：旧占位会自动挪进回收站。接手后先运行 `git status`，有对方留下的未存档改动就对着反馈单逐条审，对的留、半截的补完，单独存档，不混进本次存档，并告诉用户。
- 没有占位：直接建好。再运行 `git status`，发现不属于本次的未存档改动，要先告诉用户，不要混进本次存档。

**写 Python 的一条坑**：Mac 自带的 Python 3.9 遇到超过约 1000 字节、带中文的一行，又没写编码声明时，会误报 “Non-UTF-8 code” 拒绝运行。新建 .py 文件第一行写 `# -*- coding: utf-8 -*-`（`bin/test_py39_long_lines.py` 会查长中文行的文件有没有写）。

**改完后存档。** 先理解代码、做最小改动，再运行 `bash bin/run_tests.sh`（全部离线回归，任何失败即返回非零）；只有它显示“全部测试通过”才能继续：
1. 根目录 `VERSION` 改为 `YYYY-MM-DD.N`（当天第 N 次；2026-11-24 起全家一个版本号），在根目录 `CHANGELOG.md` 末尾加一句修改记录（本文件夹的 `CHANGELOG.md` 是合并前的记录，不再追加）；行为变化同步更新 Skill/说明文档。
2. `git add -A`（整个程序目录是一个仓库，2026-11-24 起；存档一次就把改到的各文件夹一起存了），确认暂存区没有 `secrets/`、`__pycache__`、`正在修改中.txt`，再 `git commit --author "修改人姓名 <邮箱或 none@local>" -m "MM-DD 修改人：一句话中文说明"`，让记录里能看出是谁改的。
3. `python3 ../bin/placeholder.py release` 放掉占位，告诉用户版本号，并说明这时使用版还没变、发版后才用上（发版后提醒新开对话；审核网页看根目录 `VERSION`，版本变化后自动重启）。

测试未通过不存档，说明情况由用户决定继续或放弃（放弃即恢复到上一存档）；无论结果如何最后都放掉本次的占位（`release`）。

**用户的中文说法**
- “列出最近的修改记录”：`git log --oneline -20`，中文列出时间、修改人、说明。
- “退回到某个版本”/“撤销某次修改”：先占位，列出将变化的文件并获确认，用 `git revert` 生成新存档，不用 `reset --hard`（在开发版做，再发版；要把使用版整个退回上一次发版之前，用开发版根目录 `python3 bin/release.py rollback`）。
- “整理经验”：用 thinkcut-feedback；`经验/待审/` 里以前留下的按 `internal/经验/口播剪辑旧经验/README.md` 汇总给用户逐条决定。
- “清除修改占位”：`python3 ../bin/placeholder.py check` 看一眼，过期的直接接手；还有效的告诉用户是谁在改，用户确认后 `release`。
