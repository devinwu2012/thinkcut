# 分镜规格.json 怎么写

`beats` 命令把它编译成 `分镜.json`（带秒数）。动画、小圆圈、音效和达芬奇都读编译后的文件，**不要手改 分镜.json**。

完整例子是 `samples/烟道反味/分镜规格.json`，烟道那条的原样。用 `beats` 编译它，结果和当时成片用的分镜逐字一致。

## 结构

```json
{
  "end": 190.123,
  "anchors": { "hook": ["没到饭口", 0], "valve": ["止逆阀", 18.5, -0.05], "fixed": ["这样才能补得住", 59] },
  "shots": [
    { "id": "B_valve", "a": "valve", "b": "claim" },
    { "id": "B_board", "a": "stick", "b": "step3", "warp": [["stick", 6, 0.36], ["hold", 6, 0.52], ["step3", 6, 1.0]] }
  ],
  "pip": { "min_seconds": 6, "right": ["B_old"], "never": ["B_summary"] },
  "sounds": { "POP": "UI+弹出，弹出+6.mp3", "ZOOM": "唰音效刷出标题.mp3" },
  "gain": {},
  "sfx": [["valve", "POP"], ["step1", "TECH", -0.765, "lead"], ["seven", "TICK", 0.47]]
}
```

- **anchors（卡点）**：`名字: [词, 从哪之后找, 偏移秒, 取词尾]`，后三项可以省。
  - 词按口播里实际说的字找（字幕纠错之后的字）。
  - **从哪之后找**（2026-11-12《水电阶段》：写秒数的话换口播、删句后秒数全错）：新写的卡点写 `null`（在上一个卡点之后找）或另一个卡点名（在那个卡点之后找），不要再写秒数。重跑 beats 时“上一个”按上次 分镜.json 里的时间排，所以换口播、删句后照样对得上（《水电阶段》占位口播换真口播：115 个卡点全部对上）。老片子规格里的秒数在重跑时只用来给新卡点排先后；要照老办法按秒数找，规格里写 `"找法": "秒数"`。
  - **新卡点写 `null` 就行，不用写秒数**（2026-11-22 261122 反馈单 新6：dalishi、kezhu 写“从哪之后找”报“绕成了圈”“找不到”，只好写死秒数）：`null` 的新卡点从**上一个镜头的卡点**往后找（它是镜头的 b 就从同一镜头的 a 找，是镜头的 a 就从前一个镜头的卡点找）；书写顺序的前一个卡点要是正写着“在它之后找”，会自动跳过，不再绕圈。从头找写 `"开头"`。
  - 报“绕成了圈”“找不到”时，报错里直接给出能照抄的写法（`"名字": ["词", "卡点名"]`）和起找点前后各十来个字的口播原话、这个词在口播里每次说到的秒数，照抄那一行重跑 beats。
  - 原话找不到（换口播后说法变了）会去掉头尾的字缩短再找（最短到原话一半，只在起找点之后 60 秒内），beats 会列出每个缩短对上的卡点，逐个核对。
  - 偏移是负数时提前，比如 -0.05 表示提前 0.05 秒。
  - 取词尾写 true 时，取这个词最后一个字的结束时刻。
  - 找不到会报错并告诉你是哪个词。同一个词出现多次时，按顺序写，或用“在某卡点之后找”区分；和上一个卡点同一个词时，找的是下一次说到它。
- **end**：全片到第几秒为止。**不用写**，默认就是成片的长度（`init` 从口播交付读的帧数）；只有想让分镜比成片短时才写秒数。（2026-11-23 初稿模式实测：短片不知道要不要写）
- **shots（动画镜头）**：`a`、`b` 写卡点名或秒数；第一个镜头从头开始写 `"a": "开头"`，最后一个到片尾写 `"b": "片尾"`（2026-11-23，不用抄成片秒数）。镜头之间的空档自动补成人脸镜头（F）；镜头不能重叠。
  - `warp`：动画工程里有一整段写好的动作（timeline.js 的第几段、段内百分比）时，用 `[卡点, 段号, 百分比]` 把“说到这个词”对上“动作做到这一步”，中间按比例伸缩。这是烟道遗留用法，新题材一般不用，直接按镜头 id 在 `src/62_beats.js` 里写。
  - 没有 warp 的镜头，由动画工程 `src/62_beats.js` 里按镜头 id 写的相机和状态来画。
- **导演分镜**（2026-11-13 起，Q045：口播要点只写这一份，不再另写动画工程里的 `镜头.json`；老片子已有的照读，两处都写了以这里为准）：动画镜头里再写这几项，`anim-confirm`、`anim-gate`、Blender `出片.py` 都从这里读，beats 不拿它们算时间（只在画面写到地图时提醒一句）：
  ```json
  {"id": "A01", "a": "toilet", "b": "fan_end", "工程": "Blender_通风",
   "讲什么": "关系", "口播要点": ["马桶和淋浴间挨着放", "换气扇装在淋浴间正上方"],
   "画面": "全景看整个卫生间 → 0.7 秒推到淋浴间顶上的换气扇", "运镜": "全景 → 中景（推）"}
  ```
  - `讲什么`：关系/对比/档位/过程/结构/场景之一；前三种做动画前必须先出逻辑草图给用户逐条对照确认（见 动画做法.md 第 6 节）。
  - `口播要点`：对应的口播原话要点，一句一条；草图确认时每条要一个 `--check "要点=画面里怎么表现"`。改了要点或画面，之前的样张确认作废。
  - `画面`、`运镜`：从哪到哪、几秒（导演思维：全景→中景→特写怎么过渡）。
  - `画面` 不写地图（2026-11-21《装修最后那点细节》，用户：“不要把地图画那么明显……能看清楚是个异地的感觉就行”）：讲异地、多城市写“以某城市为圆心的距离圈，不画任何地图边界”。`画面`、`讲什么` 写到 地图、国界、省界、省份、边界线、行政区（同一个半句里写了“不画/不用/无……”的不算）时，`beats` 提醒、出样张和出片前停下；规则和放行办法见 动画做法.md 第 6 节第 1 步。
  - `工程`：Blender 镜头写所在工程文件夹名（`Blender_<名字>`），`出片.py` 不写 `--shot` 时出这些；代码动画（`动画/`）可不写。
  - 场景不是房间的 Blender 镜头写 `"不涉及布局": "原因"`。
- **实拍和图片**（2026-11-21 新增，《别墅装灯》以前要在片子里写脚本、手改 `合成/动画清单.json`、`合成/渲染尺寸.json`）：镜头里写这几项，`beats` 编进 分镜.json，`anim-assemble` 自动做成本片画幅、正好帧数的片段（放在 `合成/实拍镜头/`）、登记（100%）、拼进 B肉；源文件、入点没变就不重做。路径写绝对路径，或相对片子目录、02_制作。
  ```json
  {"id": "R13", "a": "zuofa", "b": "meiyou", "实拍": "实拍/R13_现场试灯.mp4"},
  {"id": "R02", "a": "flos", "b": "liang", "实拍": {"文件": "../01_原始素材/B roll/xx.MOV", "入点": 10.0}},
  {"id": "R12", "a": "ruguo", "b": "danna", "图片": ["临时/模拟图1.png", "临时/模拟图2.png"], "铺法": "完整"},
  {"id": "B05", "a": "liding", "b": "meiguan", "工程": "动画", "讲什么": "档位", "口播要点": […],
   "盖实拍": [{"从": "gongren", "文件": "实拍/试灯_定格画线.mp4", "入点": 0}]}
  ```
  - `实拍`：整个镜头放一段实拍。写路径，或 `{"文件": 路径, "入点": 从源文件第几秒起}`。画幅不同时等比放大铺满、居中裁；从入点起不够镜头长度会停下。
  - `图片`：整个镜头放图，几张就平分时长；`铺法` 写 `完整`（默认，整张放进画面区，空的地方是动画底色）或 `裁满`（铺满画面区、裁掉多的）。
  - `盖实拍`：动画镜头里某一段换成实拍，可以写几段（不能重叠）。`从`、`到` 写卡点名或秒，不写就是镜头开头、结尾。这一段动画照常出，总装时被实拍顶替；**这一段动画标签不画、标签自检不查**（成片里看不见）。
  - **AI 生成的图不加角标**（2026-11-22 用户定：“所有AI生成的都去掉，右上角‘AI生成’提示标签都去掉，以后都注意”）：Codex 生图、往期的 AI 对比图，一律不加“示意图／AI 生成”这类角标；沿用往期带角标的图时换成没角标的原图。`beats` 看到镜头用的文件名带 `_标注`／`角标`／`AI生成` 会提醒。
  - 镜头 id 照旧用 R 开头表示整段实拍/图片；写了 `实拍`/`图片` 的镜头代码动画不画、标签自检不查。实拍原声要放进审核线的，照旧走额外轨道清单。
  - 跟着画面动的标注线（光流跟踪）、定格画线这类特殊效果不在这里做：先在片子里做成一段实拍片段，再用 `实拍` / `盖实拍` 登记。
  - **`占位图`**（2026-11-22 用户定“先做出来再改”：“没有这个素材什么的，它就自己生成，或者用……生图先做上……我有了之后我再替换”）：这个镜头该放实拍或图片、但手上没有素材时（先查过素材库和往期），写画面描述，先用生成图占位：
  ```
  {"id": "R03", "a": "sanshi", "b": "shufu", "占位图": "客厅吊顶，一排筒灯离墙 30 公分，光均匀洗在白墙上"},
  {"id": "R04", "a": "shiwu", "b": "liushi", "占位图": ["同一面白墙：筒灯离墙 15 公分，墙上一排又尖又亮的扇贝形光斑", "同一面白墙：筒灯离墙 60 公分，墙面是暗的"]}
  ```
    - 描述写成“画面里有什么”，一个场景一条；口播在列举、对比几个场景时**一个场景一张**，写成列表（同一组对比会同机位、一次出齐），和下面「画面数量」的规矩一样。不写“AI 生成”“示意图”，图上不加任何角标和字。
    - `beats` 把它编成图片镜头（图放 `实拍/占位图/<镜头>.png`，几张是 `_1`、`_2`…；`铺法` 不写默认 `裁满`），`placeholder-images DIR` 用 Codex 生图把缺的图生成出来（已有的不重出，`--shots R03` 只生成某几个，`--force` 重出、旧图改名留着），再 `anim-assemble`。生成失败会说是哪个镜头，重跑只补缺的。
    - 不能和 `实拍`、`图片` 同写。**用户给了真素材**：把这个镜头的 `占位图` 删掉、写 `实拍` 或 `图片`，再 `beats` → `anim-assemble` → `pip` → 建新一版审核线。
    - 写了 `占位图` 的镜头就是占位：审片台审核线栏头下面那行“占位 …”、时间条上的斜纹、`status` 都从这里读，不另记清单。
    - **占位图只给需要真实场景、真实质感、真人的镜头**（2026-11-23 初稿模式实测后定）：讲结构、尺寸、位置、原理、步骤、对错对比的镜头做动画，不写占位图；`beats` 看到占位图镜头的口播要点、画面里有数字单位、离地／间距、第几步、对错这类词会提醒，全片没有一个动画镜头也提醒（不拦，确实该用图的不用改）。
    - `placeholder-images` 出完会拼一张 `实拍/占位图/总览.jpg`（顺序见 `总览_顺序.txt`）：**先自己逐张对口播看一遍再往下做**，画错的 `--shots <镜头> --force` 重出一次。
  - **`文字卡`**（2026-11-23）：机器配音的片子里自我介绍、结尾引导关注这类“本该露脸”的句子，写 `{"id": "R09", "a": "woshi", "b": "片尾", "文字卡": ["我是<IP 名>", "关注我"]}`（一到三行；写什么话按这个 IP 规矩的「品牌和口吻」）。`beats` 自动画一张深底白字的中性字卡（`实拍/文字卡/<镜头>.png`，第一行大、后面小，字没变不重画）当这个镜头的画面；不算占位图，不花生图额度。不能和 `实拍`、`图片`、`占位图` 同写。
- **pip（小圆圈）**：连续动画超过 `min_seconds`（默认 6 秒）时，整段放人脸小圆圈。
  - 默认放卡片左下。段里有 `right` 列出的镜头时放右下，用在左下有重要画面的情况。
  - **任意位置、分段换位置**（2026-11-12《水电阶段》用户：圆圈要躲开画面主体，放在任意位置都可以）：`"pos": {"R31": "TL", "R12": [[0.42, "BL"], [1, "TR"]], "R99": [1500, 900], "R40": "none"}`。位置 = `TL/TC/TR/ML/MC/MR/BL/BC/BR`（上中下×左中右；左下、右下和原来一样，上排在导航条下 70 像素）、`[x, y]`（4K 圆心坐标）或 `"none"`（这段不放）。分段写 `[[到哪, 位置], …]`，“到哪”是镜头时长的几成（0–1）或卡点名。写了 pos 的镜头即使不够 6 秒也放。
  - `never` 里的镜头不放，比如左边是清单的镜头。
  - `subs-check` 判“字幕压到小圆圈”用和 `pip` 烧圆圈同一套位置：认 `pos` 的新位置、分段、`none` 和推近时的缩小（2026-11-13；以前只按左下/右下两个固定位置判）。
- **推拉文件**（2026-10-24 新增，推荐）：`"推拉文件": "动画/推拉.json"`，内容是 `[{"shot":"S05","t0":46.638,"t1":47.338,"kind":"in"}, …]`（合并各组子助手交回的推拉起止）。推拉默认不响（2026-11-12：音效只放重点、“唰”少用）；写 `"push_sound": true` 时 beats 给每次推拉起点加一声 `ZOOM`。beats 会给带小圆圈的镜头自动加缩小时段（推近起点到拉回终点，没拉回就到镜头结束）。手写的 sfx 和 pip.shrink 照样保留，重复的跳过。
- **pip.shrink**（2026-10-23 新增）：`[[起, 止], ...]`（卡点名或秒）。镜头推近讲重点的时段里，小圆圈平滑缩到 `shrink_to`（默认 0.64，即原直径的 64%），左下/右下角对齐不动；两端过渡 `ramp` 秒（默认 0.7，和推拉时长一致）。用户要求：镜头推近讲重点时小圆圈给画面让位。
- **sounds**：代号对应花字音效收藏表（NAS 上 `<程序目录>/口播剪辑/engine/config/sfx_favorites.json`）里的文件名；项目里自己下的音效写路径（相对 02_制作，如 `素材_音效/mixkit_11-12/xxx.wav`，或绝对路径），整段使用、起音自动找。`synth:xxx` 是本能力自带的合成声（`assets/sfx/synth_xxx.wav`），目前有 brush（刷墙）、crack（开裂）、hiss（漏气）。
- **sfx**（2026-11-12 起新写的都用这种写法，只放重点）：
  ```json
  {"at": "r01b", "sound": "SLICE", "beat": "主题", "why": "墙一封就没机会了"},
  {"event": "光纤设备", "shot": "A21", "sound": "CLICK", "beat": "画面重点", "why": "光纤设备出现"}
  ```
  - `beat` 必写，只能是：开场钩子、主题、章节转场、关键数字、结论、画面重点。全片平均每分钟不超过 8 个（job.json `sfx_per_minute` 可改，用户点名要更密才改）。
  - **大字和结论类音效卡在关键词上**（2026-11-21《别墅装灯》：卡点写成“但那是营销行为”句首，音和字早约 0.3 秒，用户：“音效要卡点”）：卡点词直接写关键词本身（被高亮的那个词，如 `["营销行为", …]`，不写整句），口播大字（花字.json 的 `at`）同样从关键词起。`check` 拿大字出场、`beat: "结论"` 和落在大字上的音效，和关键词起点比（大字取 `lines` 里【】〖〗括起来的词、人挡字取它的字，结论音效取那句字幕的蓝色重点词），差超过 0.15 秒就报；`sfx` 遇到音效差超过 0.15 秒直接停、不写音效表（2026-11-22 升成硬拦），用户听过认可这样卡才 `sfx DIR --allow-sounds`（音效表里记“放行”，check 只提醒）。**以说明为准、程序已改齐**（2026-11-24 初稿模式第二次实测：差 0.32 秒 `sfx` 没拦，因为 `sfx` 在 `subs` 之前跑、字幕表还没有，找不到“那一句”；现在字幕表没有就按 job.json 的交付 SRT 找句子，所以 `sfx` 一定会拦；也要求 job.json 的 `srt` 先填好、`subtitle_keywords` 先写）。人挡字例外（用户定）：它是铺在人身后的背景字，可以比关键词早出现，只查晚了的；配它的音效卡它的出场或卡关键词都行。
  - `at` 写卡点名或秒；`event` 写画面事件名字里的字（`shot` 限定镜头，同名多个用 `nth` 第几个），时间从当前进成片那一版动画的事件表取（`合成/动画清单.json` 登记的），找不到、或事件时间不在那个镜头里，beats 会停。
  - `d` 偏移秒；`role: "lead"` 时按片段起点放，不对起音，用于需要提前铺垫的音效。默认让这个音效最响的一下落在卡点上。卡在片头（0 秒附近）、起音前那一小段要从 0 帧之前放才对得上时：从 0 帧放、去掉选段开头放不下的那几帧，起音仍对准卡点，`sfx` 会在输出里注明（音效表里记 `head_cut`）。
  - 老写法 `[卡点名或秒, 声音代号, 偏移秒, 角色]` 还认（烟道等老片子），但不带 beat，check 没法按类别放过露脸段的字幕变色音效。
  - 音效由项目脚本生成时写 `"音效脚本": "合成/音效节拍表.py"`，beats 每次写完 分镜.json 自动重跑它；分镜规格没写 sfx 也没写脚本时，beats 沿用上次 分镜.json 的音效并提醒（不会清空）。
- **gain**：一般留空，音量按规范自动定：每个音效选段峰值调到约 -5 dBFS；长于 1 秒的持续声（冲水、气声）再压到最响处比人声平均响度低 6 LU。只有用户点名要某个音效更大/更小时，才按声音代号写 dB（写了优先）。

## 怎么分镜（烟道那条的做法）

- **露脸（F）**：开头钩子、讲观点、讲经历、结尾引导关注。
- **上动画（B）**：讲结构、原因、步骤、材料、错误做法时。只有文案、缺素材时也一样：讲结构、尺寸、位置、原理、步骤、对错对比的镜头做动画，只有需要真实场景、真实质感、真人的镜头才用占位图（2026-11-23，见 初稿模式.md「什么时候做动画，什么时候用占位图」）。
- 一个动画镜头讲一件事，长度跟着话走：短的 1–3 秒，比如“止逆阀”一闪；长的 10 秒左右，比如一整步施工。
- “第 N 步”这类小标题之后，通常先露脸说一句，再上动画。
- **口播在列举、对比几个场景时，一个场景一张图／一段镜头**（2026-11-22 用户定：“有人看投影，有人看电视，那其实是2个场景。2个场景你还用1张图，那就不合适了”）：A 对 B、几种家庭情况、几种材料，每个场景单独一个画面，卡在说到它的那个词；同一组对比用同一个机位、只换要比的那一项；生图时这一组一次都出齐。`beats` 发现一个图片镜头里的图比它盖住的关键词条（花字 `keywords` 逐个出的词）少，会提醒。
- 动画里每个动作都要有卡点：说到“钢丝刷”时刷子出现，说到“界面剂”时开始刷。
- 常用音效：
  - 标签、物件弹出：POP。
  - 转场：WHOOSH。
  - 警示“千万别”：ALERT。
  - 结论、做对了：DING。营销、商家套路这类“反面”结论用错误音（项目里下的“错误-嘚嘚”，写路径 `素材_音效/…`，2026-11-21 用户定）。
  - 口播大字、人挡字：配叮、点击、错误音这类，不配“唰”（WHOOSH、ZOOM；2026-11-21 用户定，check 会报）。
  - 数字、标准号：TECH。
  - 章节卡：TYPE，加提前约 23 帧的 TECH lead。
  - 清单逐条出现：TICK。
  - 刷、抹：用素材库里的真实刷声（没有就先问用户下载哪条）；不用合成音。
  - 资料下划线：MARKER 马克笔（一秒内连着几道只响第一道）；划掉、打叉几天：SLASH 纸一划；ZOOM“唰”（唰音效刷出标题.mp3）2026-11-22 进黑名单（用户三次否掉），`sfx` 选到会停，大的推近、强调改用别的；刮掉浮浆这类轻刮：SCRAPE 沙沙（不要角磨机）；喷水：SPRAY（从喷的那帧起）；材料刷上去、渗进去：BUBBLE 水泡（2026-11-01 用户在《别墅地下室防水》试听选定）。
  - ✓✗、动画进场不响。
- 音效按画面上发生的事放，同一类事全片同一个声音（见 动画成片.md 第 8 步）。
- 音效只放重点（见上面 sfx 的 beat）：平均每分钟不超过 8 个；一个镜头 2 秒内别超过两声。
